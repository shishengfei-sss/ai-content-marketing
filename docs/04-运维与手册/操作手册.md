## 1. 系统概览

**产品形态**：通用 AI 营销创作 + 内置 SaaS CRM。一句话主线：

```
AI 创作 → 活动关联 → 线索/客户 → 商机 → 报价/合同 → 订单 → 回款/发票
                                  ↘ 运营报表与提醒
```

**版本交付线（基线 Alembic head 随版本递增，v1.3 为 `083`）**：

| 版本 | 内容 | 状态 |
| --- | --- | --- |
| MVP / v0.3.x | 账号/多租户、知识库、创作、审核、发布 Mock、Web+H5 骨架、平台额度 | ✅ |
| v0.4 | Agent 半智能体 + Workflow（propose/resume）双端 | ✅ |
| v0.5～2f | 线索/客户/任务/活动/销售组织/自定义字段/导入/视图；CRM 缺口收尾 | ✅ |
| v0.6 / 0.6.1 | 统一营销顾问、Prompt 分层、人格锁定、合规自检 | ✅ |
| v0.7 | 商机管道→产品→报价→合同→订单→回款全链路 | ✅ |
| v0.8 | 商机字段/跟进/附件/明细→报价、团队、漏斗、超时/预测/赢输 | ✅（审批除外） |
| v0.9 | 线索客户统一、转化去重、评分/公海/BANT/360、通知铃铛、导出、培育/UTM/ROI | ✅ |
| v1.0 | 订单审批/税率、合同模板、产品分类、发货/发票/修订、退款 API、渠道 ROI | ✅ |
| v1.1 | 创作白屏修复、活动关联贯通、SSE、异常脱敏、合规改稿、会话恢复 | ✅ |
| v1.2 | 交易报表、回款/合同到期提醒、分配规则 UI、发票核销/退款 Tab | ✅ |

**下一步（≥v1.4，未立项）**：创作效果闭环（A/B、发布回流）、财务售后闭环（退货/红冲/对账单/坏账）。

**技术栈**：FastAPI + SQLAlchemy + Alembic（API）；Vue + Vite（Web）；uni-app（H5）；PostgreSQL + pgvector（生产）；DeepSeek / OpenAI 兼容 LLM（可插拔）；Nginx 反代。

## 2. 系统架构

```
                ┌─────────────┐        ┌─────────────┐
   浏览器/微信H5 │  Web (Vue)  │        │  H5 (uni)   │
                │  静态资源    │        │  静态资源    │

                         │ Nginx / 网关    │  反代 /api、/storage
                         └────────┬───────┘

                         └────────┬───────┘

| 组件 | 目录 | 构建产物 | 配置 |

**目录结构**：
```

## 4. 本地开发搭建

### 4.1 启动 API

```powershell
cd e:\ai-content-marketing\apps\api
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\alembic upgrade head
.\.venv\Scripts\uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```
验证：`http://127.0.0.1:8000/health` → `{"status":"ok"}`

> Web/H5 通过 Vite 代理访问 API（`VITE_API_PROXY_TARGET`），须与 uvicorn 端口一致。
> 开发期默认 SQLite（`apps/api/dev.db`）；生产改 `.env` 的 `DATABASE_URL` 为 PostgreSQL。

- **方式 A（环境变量）**：复制 `.env.example` → `.env`，填 `DEEPSEEK_API_KEY=sk-你的key`

### 4.3 启动 Web

```powershell
cd e:\ai-content-marketing\apps\web

npm.cmd run dev
```
打开 Vite **Local** 地址（默认约 5173）→ `/login` 手机号登录。

### 4.4 启动移动端 H5

```powershell
cd e:\ai-content-marketing\apps\mp
npm.cmd install
npm.cmd run dev:h5
```
浏览器 F12 手机模式 → 终端 **Local** 地址（默认约 5174）→ `#/pages/login/login`

### 4.5 内容获客商城演示（开箱）

账号表、种子、三端端口与演示剧本见 **[内容获客商城-本地演示启动.md](./内容获客商城-本地演示启动.md)**。仓库根执行 `scripts/start-shop-demo.ps1` 升库并写入演示数据。

## 5. 配置参考（环境变量）

### 5.1 API（`apps/api/.env`，模板 `.env.example`）

**必须修改（生产）**

| 变量 | 说明 |
|------|------|
| `DATABASE_URL` | PostgreSQL 连接串，例 `postgresql+psycopg2://user:pass@host:5432/ai_marketing` |
| `JWT_SECRET` | JWT 签名密钥，**勿用默认值** |
| `LLM_ENCRYPTION_KEY` | 租户 LLM Key 加密密钥，**≥32 字节** |
| `CORS_ORIGINS` | 允许跨域的前端域名，逗号分隔（勿用 `*`） |

**建议配置**

| 变量 | 默认 | 说明 |
|------|------|------|
| `DEEPSEEK_API_KEY` | 空 | 平台默认 LLM；也可在「设置→AI 模型」配 |
| `LLM_PROVIDER` | `deepseek` | 也可配 OpenAI 兼容 |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | `https://api.openai.com/v1` / 空 / `gpt-4o-mini` | OpenAI 兼容 |
| `LLM_TIMEOUT_SEC` | `60` | LLM 请求超时（秒） |
| `STORAGE_DIR` | `./storage` | **须挂持久卷** |
| `WECHAT_PUBLISHER` | `mock` | `mock` / `real`（真实微信需备案与服务号） |
| `PUBLISH_POLL_SEC` | `30` | 定时发布轮询间隔 |
| `JWT_EXPIRE_MINUTES` | `10080`（7 天） | Token 有效期 |

**短信（当前仅 Mock）**

| 变量 | 默认 | 说明 |
|------|------|------|
| `SMS_PROVIDER` | `mock` | 暂无真实短信服务商 |
| `SMS_MOCK_CODE` | `1111` | 登录/找回密码 Mock 验证码 |
| `SMS_CODE_EXPIRE_SEC` | `300` | 验证码有效期 |
| `SMS_SEND_INTERVAL_SEC` | `60` | 同号发码间隔 |

> 生产 `.env` 切勿设置：`FORCE_FAKE_PLATFORM_LLM`、`VERIFY_LIVE_API`、`VERIFY_API_BASE`（仅本地验收脚本用）。

### 5.2 Web / H5（`.env.production`）

| 变量 | 开发 | 生产 |
|------|------|------|
| `VITE_API_BASE_URL` | 空（走 Vite 代理） | **必填**，如 `https://api.yourdomain.com` |
| `VITE_API_PROXY_TARGET` | `http://127.0.0.1:8000` | 仅 dev |
| `VITE_DEV_PORT` | `5173` / `5174` | 仅 dev |

可选（Agent 行为）：`VITE_AGENT_FALLBACK=1`（流失败回退旧接口）、`VITE_AGENT_WORKFLOW=0`（关闭 Workflow）。

## 8. 部署上线

### 8.1 Docker Compose（开发/演示）

```bash
# 项目根目录
export DEEPSEEK_API_KEY=sk-xxx   # 可选
docker compose up -d postgres api
```

| 服务 | 端口 | 说明 |
|------|------|------|
| `postgres` | 5432 | 用户/库 `ai_marketing` / `ai_marketing` |
| `redis` | 6379 | 当前 API **未使用**，可不启动 |
| `api` | 8000 | 启动自动 `alembic upgrade head` |

生产注意：改 `JWT_SECRET` / `LLM_ENCRYPTION_KEY` / `CORS_ORIGINS`；去掉源码挂载 `./apps/api:/app`；Dockerfile 的 `CMD` 去掉 `--reload`；为 `STORAGE_DIR` 挂命名卷。

### 8.2 手动部署

1. **数据库**：建库后 `cd apps/api && alembic upgrade head`，确认 `alembic current` 为当前基线 head。
2. **启动 API**：`uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2`（确保 `.env` 已配）。
3. **构建静态资源**：
   ```bash
   cd apps/web && npm install && npm run build        # → apps/web/dist/
   cd apps/mp  && npm install && npm run build:h5     # → apps/mp/dist/build/h5/
   ```
4. **存储目录**：API 自动创建 `{STORAGE_DIR}/published`、`/exports`、`/crm_imports`，**生产务必挂持久卷**。
5. **Nginx**：参考 `docs/04-运维与手册/v0.5-运维部署.md` §6，API 子域 + Web/H5 独立域名；Agent SSE 需 `proxy_buffering off`。确认 `CORS_ORIGINS` 含前端域名。

### 8.3 一键生产发布（`scripts/deploy-prod.ps1`）

```powershell
# 历史：曾目标机 192.168.20.200（已下线）。当前内网演示为 192.168.20.201:8088/8089，暂无生产发布机
powershell -ExecutionPolicy Bypass -File scripts/deploy-prod.ps1 -SshUser root
# 跳过构建： -SkipBuild ；跳过打包： -SkipPack
```
脚本行为：本地 build Web/H5 → 打包 API（`pack-api-deploy.ps1`）→ ssh 上传到 `/opt/shengfei/apps` → 远端 `deploy-remote.sh` 就地覆盖代码（**保留线上 `.env` / `storage` / `*.db`**，只执行 `alembic upgrade head`）→ 冒烟检查 `crm/health` 与 `openapi.json`。
本地 API 版本自检：`scripts/check-api.ps1`（检查高级筛选 `filters`、编辑姓名 PATCH 是否就绪）。

### 8.4 上线后验收

健康检查：`GET /health`、`GET /api/v1/crm/health`、`alembic current`（应为当前基线 head）。
自动化门禁：按第 7 章在部署机/CI 跑 `run_crm_all.py --through 2f`、`run_advisor_all.py`、`verify_crm_uat_f2.py`。
手工冒烟（约 15 分钟，Mock 验证码 `1111`）：登录 → 线索列表/新建（省市区级联）→ 写跟进→建任务→完成 → 线索转化客户 → 导入向导（模板→映射→预览→执行）→ Dashboard 数字一致 → editor↔sales 角色切换菜单显隐。

## 9. 日常运维

### 9.1 回滚与数据安全（铁律）

| 规则 | 说明 |
|------|------|
| 只升级 | 仅允许 `alembic upgrade head`，**禁止** `downgrade` / `drop` / 重建库 |
| 保留配置 | 永不覆盖线上 `apps/api/.env` |
| 保留存储 | 永不删除 `STORAGE_DIR` / `storage/` |
| 保留库文件 | 若用 SQLite，永不删除/覆盖 `*.db` |
| 就地更新 | API 目录就地 rsync 代码，不整目录 mv/清空 |

| 场景 | 操作 |
|------|------|
| 仅前端问题 | 回退 `dist/` 静态资源到上一版本 |
| API 代码问题 | 回退 Python 包/镜像，数据库一般不回滚 |
| 迁移有问题 | `alembic downgrade -1`（须确认安全，生产慎用） |
| 配置错误 | 修正 `.env` 后重启 uvicorn |

> 升级前备份 PostgreSQL 与 `STORAGE_DIR`。

### 9.2 安全清单

- [ ] `JWT_SECRET`、`LLM_ENCRYPTION_KEY` 已更换默认值
- [ ] `DATABASE_URL` 强密码，数据库不暴露公网
- [ ] `CORS_ORIGINS` 仅含可信前端域名（勿用 `*`）
- [ ] API 仅通过 HTTPS 对外
- [ ] `STORAGE_DIR` 权限最小化 + 持久卷
- [ ] `.env` 不入 Git（已在 `.gitignore`）
- [ ] 平台管理员账号密码已改默认值
- [ ] 生产评估 `SMS_MOCK_CODE=1111` 风险（接入真实短信前）

### 9.3 存储目录

| 路径 | 用途 |
|------|------|
| `{STORAGE_DIR}/published/` | 已发布内容静态文件（挂载 `/storage/published`） |
| `{STORAGE_DIR}/exports/` | 导出 zip（挂载 `/storage/exports`） |
| `{STORAGE_DIR}/crm_imports/` | CRM 导入任务上传文件 |

### 9.4 常见问题

| 现象 | 排查 |
|------|------|
| 前端 401 / CORS 报错 | 检查 `CORS_ORIGINS` 是否含前端域名；Token 是否过期 |
| 前端连不上 API | 确认 `VITE_API_BASE_URL` 或 Nginx `/api` 反代 |
| 迁移失败 | `alembic current` / `alembic heads`；数据库连接串是否正确 |
| 导入失败 | CSV 须含「公司名称」「联系人姓名」「手机」等必填列 |
| LLM 不可用 | 检查 `DEEPSEEK_API_KEY` 或租户设置页 Key；平台额度 |
| 忘记密码无效 | 当前 `SMS_PROVIDER=mock`，验证码固定 `1111` |
| 微信发布无效 | `WECHAT_PUBLISHER=mock` 为预期，真实接入需备案 |

## 11. Agent 智能体与提示词/人格体系

**能力层级**：会话持久化（A0~A3）→ 工具型 ReAct（B1~B4，MAX_STEPS=8）→ 长期记忆 LM1~LM5（L0 brand → L1 消息 → L2 摘要 → L3 语义事实 → L4 行为统计）→ 自治增强 C1 工作流 / C2 合规 / C3 Confirm 闸 / C4 Hybrid RAG / C5 Supervisor / C6 Seo → AG8 总验收。

**硬规则**：Agent **禁止**未经用户 confirm 自动 publish（BR-01）；不恢复强制审核流，Compliance 仅建议/拦截。

**提示词编写**（见 `docs/03-智能体/智能体提示词模板.md`）：提示词只写「宪法」（角色边界/行为规则/禁止项）与「人格」（稳定底色 + 从人格库动态加载变体）；**禁止**写产品价格、FAQ、业务流程、API 逻辑。

**人格库**（见 `docs/03-智能体/人格库设计手册.md`）：v0.6 起创作页统一使用 `marketing` 顾问，管理后台菜单为「营销顾问配置」，人格库 P-001~P-009。
