## 1. 严重问题（ blockers，必须先解决）

### 🔴 S1 · 计划/用例「双源」并存且未统一
- **现象**：A、B 两份执行计划 + 两套测试用例库同时存在。A 被索引且被交付标准/QC/分册交叉引用；B 自成体系、未被索引，但 B 里有更具体的可执行细节（写死的账号、端口、stub 变量、500+ 细粒度用例）。
- **风险**：执行者不知道以哪套为准；编号三套并存（VS-M* / TC-* / VM*·VS*·E2E*）；Q1「QA R6 报告 Pass」在 B 里对应的是 Round 7，含义完全不同；验收无法客观判定。
- **建议**：
  1. 以 **A 为唯一执行基线**（已被索引、链路完整）。
  2. 将 B 中**有价值的具体化**（见 S2/M2/M3/M4）回写进 A 的对应位置。
  3. B 两份文件**归档至 `06-归档/`**（或改写为"执行级用例明细"并明确标注"从属 A、编号以 TC-* 为准、变量以 `*_PROVIDER=mock` 为准"），且必须补入 `docs/README.md` 索引（否则违反文档组织规范「索引同步」铁律）。

### 🔴 S2 · 版本交付线梳理基线严重过时（090 vs 实际 103）
- **现象**：`00-总览/版本交付线梳理.md` 第 3/33/117 行反复声明「v1.6 = Alembic 090」「版本交付线已到 v1.6…Alembic 090」；但仓库实际 head=**103**，且 091–097 这批迁移**在全文无任何归属说明**。
- **风险**：所有"以 v1.6=090 为基线"的后续判断都错；091–097 成了文档盲区，可能掩盖未记录的迁移。
- **建议**：将基线更新为「当前 head=**103**」；在版本表中补全 091–097 的版本/批次归属（或确认它们属于某次未记录的改动）；与执行计划 §1.4（102 结算骨架、103 权限微调）对齐。

## 2. 中等问题（应在签收前修正）

### 🟠 M1 · 交付标准「D1～D8」编号笔误
- **位置**：`内容获客商城-开箱即用交付标准.md` §2.2 只定义 **D1–D7**，但 §11 签收页写「研发负责人：D1～**D8** 交付包齐全」。
- **修正**：签收页改 `D1～D7`；或补一条 D8（如"录屏/对外演示物料可选件"）。

### 🟠 M2 · 买家端形态在 A 中未钉死
- **现象**：A 执行计划 §13 / 交付标准 §3·§7 反复写「小程序/H5（**约定形态**）」「Phase1 不做独立 H5 商城」，未明确。
- **已知事实**：工作记忆铁律 = `5173`=web(Vue3)、`5174`=mp(uni-app H5)；B 已钉死「Web 5173 / Mini-Program H5 5174」。
- **修正**：A 交付标准 §3/§7 直接写明「买家端 = `apps/mp` H5（端口 **5174**），作为演示形态；独立小程序为后续」，消除"约定形态"歧义。

### 🟠 M3 · 平台管理员密码等未写死
- **现象**：A 交付标准 §4 演示账号表写「密码与主站约定一致」「seed 指定」——未落地。
- **已知事实**：后端实际落地 `13800000000 / admin123456`，mock 短信验证码固定 `1111`（工作记忆铁律）。
- **修正**：交付标准 §4 直接写死 `13800000000 / admin123456`，并在启动说明补「mock 验证码=1111」；或明确"以 seed 脚本为准、脚本落地后回填"。

### 🟠 M4 · Mock 环境变量命名冲突
- **现象**：A 执行计划 §0.5 用 `SMS_PROVIDER=mock`、支付/公域用「Mock notify / Mock Webhook」字样；B 完整用例用 `WECHAT_PAY_MODE=stub` / `DOUYIN_WEBHOOK_MODE=stub` / `SMS_MODE=stub` / `COURSE_LIB_MODE=stub`。
- **风险**：若 A、B 脚本并存，会出现"到底哪个变量生效"的歧义，演示/自动化可能读错开关。
- **修正**：统一为一套（建议沿用 A 的 `*_PROVIDER=mock` 风格，并把支付/公域也显式写成 `WECHAT_PAY_PROVIDER=mock` / `DOUYIN_WEBHOOK_PROVIDER=mock`），在 A 执行计划 §0.5 与种子/启动说明中一致落地。

### 🟠 M5 · 用例编号三套并存、缺映射表
- **现象**：A 执行计划章节内用 `VS-M1-01~09`；A QA 分册用 `TC-*`；B 用 `VM*/VS*/E2E*/MOCK*/SEC*`。A 执行计划 §0.4 称"用例 ID 映射 QA 库 TC-*"，§2 又称脚本用 `VS-Mn`，但**全文无 VS-M* ↔ TC-* 的逐条对照表**。
- **修正**：在 A 执行计划各批次或 QA 分册 §6 增加「执行计划 VS-M* ↔ QA 分册 TC-*」对照表；B 回并后删除其独立编号。
