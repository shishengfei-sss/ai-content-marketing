## 0.2 测试分层（前后端一起）

```text
                    ┌─ R2 平台 Web 联测 (20)  ─┐
用户可见功能验收 ──┼─ R2 商家 Web 联测 (20b) ─┼─ 必须：页面操作 + Network + UI
                    ├─ R3 买家联测 (21)       ─┤
                    └─ R4 E2E (22)            ─┘
                              ▲
                              │ 同业务对照
                    R1 API (10～17)  合同/边界/幂等/IDOR（脚本可跑）
                              │
                    R5 Mock / R6 安全 / R7 回归 / UX / 开箱
```

**完成定义**：某功能「测完」= 对应 **联测金标准或端页联测** Pass + 相关 R1 边界 Pass（或 Blocked 诚实）。  
**错误定义**：只跑通 Postman/pytest → 勾端页 Pass。

## 1. 对他方稿的核对结论


来源：归档 [商城Phase1-他方完整用例原稿.md](../../../06-归档/05-测试与验收/商城Phase1-他方完整用例原稿.md) + [shop-test-spec-html](../../../06-归档/05-测试与验收/shop-test-spec-html/)。

### 1.1 合理、应保留

| 项 | 说明 |
|----|------|
| **六段式用例** | 前置 / API·页面 / 请求·步骤 / 期望 / 边界值表 / 业务场景表 — **采纳为 v3 标准** |
| **七轮架构** | R1 API → R2 Web → R3 买家 → R4 E2E → R5 Mock → R6 安全 → R7 回归 |
| **依赖顺序** | M0→M1→M2→M4→M5→M3→M6→M7（支付依赖订单） |
| **边界值嵌在主用例下** | `-Bn` 表 + `-Sn` 场景表，避免只写大纲 |
| **Mock / 安全专轮** | 我们 v2 偏弱，v3 已补 [23](./23-R5-Mock外部.md)·[24](./24-R6-安全PII.md) |

### 1.2 错误或需纠正（写用例时禁止照抄）

| 问题 | 正确约定 |
|------|----------|
| 关联执行计划写成 `商城Phase1-M1至M8-执行计划.md` | 用 [内容获客平台-执行计划.md](../../../02-执行计划/内容获客平台-执行计划.md) |
| API 端口写死 `8000`；UI 写 `8000` | **TestClient** 基址常为 `…:8000/api/v1`；本机 live 多为 **`8003`**。用例写相对路径 `/auth/login`，基址见环境表 |
| 登录体只有 phone/password | 可带 `workspace_mode`: `platform` \| `merchant`（见 `LoginRequest`） |
| 路径偶发 `/api/v1/shop/...` 与 `/shop/...` 混写 | 统一：**相对 `/api/v1` 之后**，如 `/shop/...`、`/admin/shop/...`、`/auth/login` |
| UI 大量 `data-testid=...` | Phase1 前端多未落地；R2 **先按可见文案/角色定位**，testid 落地后再改硬选择器 |
| 商家账号示例与 seed 未对齐 | 以 [27 开箱](./27-开箱交付验收.md) / 启动说明填实值为准 |
| 「500+ 全 PASS」统计含水 | 主用例 + 边界变体分开计；Blocked 不得算 Pass |
| 根目录 `shop-test-spec/` | 已迁入 `docs/06-归档/`（文档不得放仓库根） |

### 1.3 他方有、我们 v2 缺 → v3 已补

## 3. 七轮与硬门槛

| 轮 | 通过标准 |
|----|----------|
| R1 | API 合同/边界 PASS；**不能单独当端验收** |
| **R2/R3** | **前端操作 + Network + UI**；[02 金标准](./02-前后端联测金标准.md) 写操作必过；未交付页 → Blocked |
| **UX** | [26](./26-UX专家走查.md) CONS/UX/VIS；单页均分 ≥1.5；与联测并列，缺一不可交付 |
| R4 | E2E 仍走 UI 串联；H1～H3 等证据 |
| R5 | Mock 档全绿（真机可选） |
| R6 | 安全/PII + P0 对抗 |
| R7 | `run_crm_all` / 主站回归约定绿 |
| 开箱 | D1～D7 + 产品本人冒烟 |

**开箱 ≠ 仅 R1 API Pass**。必须 [02](./02-前后端联测金标准.md) + 端页联测 + [26 UX](./26-UX专家走查.md) + [27](./27-开箱交付验收.md)。
