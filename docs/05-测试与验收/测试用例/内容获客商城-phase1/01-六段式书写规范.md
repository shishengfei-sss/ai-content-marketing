# 01 · 六段式书写规范（含前后端联测）

| 字段 | 值 |
|------|-----|
| 版本 | **v3.3** |

> **后续强制**：本仓库所有新增/改写测试用例，格式与颗粒度均按本文 + [02 联测金标准](./02-前后端联测金标准.md) + [26 UI/UX 专家走查](./26-UX专家走查.md) 执行（Cursor 规则：`.cursor/rules/test-case-standards.mdc`）。  
> **页面/版本可交付** = 联测 Pass **且** UX 专家 CONS/UX/VIS 打分通过（单页均分 ≥1.5）。

---

## 0. 总原则（强制）

**验收写操作 = 前端操作 + 后端生效，缺一不可。**

| 只测 API | 只点 UI 看文案 | **合格联测** |
|----------|----------------|--------------|
| ❌ 不能单独宣称功能完成 | ❌ 不能证明真调对接口/落库 | ✅ 页面填写/点击 → Network 出现正确请求 → UI toast/状态 → 必要时 DB/再拉列表 |

- **R1（10～17）**：允许纯 API 合同/边界/状态机（开发自测与回归脚本）。  
- **R2/R3（20/20b/21）与 R4（22）**：凡「用户可在页面完成的写操作」，**必须按联测模板**写；禁止只写 `POST /xxx` 当端页用例。  
- **宣称批次完成**：对应端页联测用例 + 相关 R1 边界 **都** Pass（或诚实 Blocked），**且** 触及的新页/改版页完成 [26 UX 专家走查](./26-UX专家走查.md)（CONS/UX/VIS）。

## 2. 前后端联测模板（R2/R3/R4 写操作强制）

```markdown
### {ID}: {标题}（联测）

**前置条件**:
- Web/H5 已启动；已用 UI 登录到正确 workspace
- 后端 API 已启动；账号/种子数据 …

**页面**: `/shop/products`（示例）
**将触发的 API**: `POST /shop/products`（须在 DevTools Network 可见）

**测试步骤（前端操作）**:
1. 打开页面 …
2. 在「标题」输入 `QA课程_日期`
3. 选择类型「课程」；填写价格 `99.00`（或分 9900，以 UI 为准）
4. 点击「保存草稿」
5. 打开 DevTools → Network，定位该次请求

**期望结果（双端）**:
- **Network**: `POST /api/v1/shop/products` → **201/200**；body 含 `status=draft`；请求价与服务端一致（防前端改价）
- **UI**: toast/提示成功；列表出现该草稿；无整页白屏
- **副作用（可选抽查）**: 刷新列表仍在；DB `shop_products` 多 1 行

**边界值测试**（优先在前端输入，再看 Network+UI）:

| 变体ID | 前端输入 | 期望 Network | 期望 UI |
|--------|----------|--------------|---------|
| {ID}-B1 | 标题清空点保存 | 不发或 422 | 红字/toast 中文 |
| {ID}-B2 | 价格 `-1` | 422 | 中文错误；列表无新行 |

**业务场景测试**:

| 场景ID | 场景 | 前端操作 | 双端期望 |
|--------|------|----------|----------|
| {ID}-S1 | 连点保存 | 1s 内点 5 次 | 仅 1 次成功创建 / 幂等同 id |
| {ID}-S2 | 无写权账号 | 打开页 | 无按钮；若抓包写 → 403 |

**结果**: ☐ Pass / ☐ Fail / ☐ Blocked
```

## 3. 规则清单

1. **路径**：API 相对 `/api/v1`；页面写前端路由。  
2. **登录**：UI 选对入口；API 带 `workspace_mode`。  
3. **联测写操作必须同时有**：前端步骤 + **将触发的 API** + Network 状态码 + UI 表现。  
4. **边界**：优先「在输入框输入非法值再点提交」，不要只用 Postman 代替端页边界（R1 可另测）。  
5. **未实现前端**：端页联测标 `Blocked(M0f/…)`；**不得**用「R1 API 绿」宣称端页完成。  
6. **中文 detail**：422/409 的 toast 应来自或对齐 API `detail`。  
7. **选择器**：优先可见文案；`data-testid` 仅代码已加时使用。  
8. **只读页**（看板/列表浏览）：至少「打开页 → 对应 GET 200 → UI 有数据/空态」。

## 4. 反例（禁止）

| 反例 | 原因 |
|------|------|
| 端页用例只有 `POST /shop/...` JSON | 未测前端 |
| 端页只有「点击保存成功」无 Network | 未证明调后端 |
| 「L01～L07 全过」 | 大纲 |
| R1 全绿就说商家端测完 | 缺 20b 联测 |
| 步骤写成 `1. —` | 无效用例 |
| 联测绿但跳过 UX 走查 | 缺 26；页面不可交付 |

## 5. 分层怎么用

```text
R1  API 合同/边界/幂等/IDOR     → 脚本 verify_* / pytest
R2  平台/商家 Web 联测           → 20 / 20b + 02 金标准
R3  买家联测                     → 21 + 02
R4  跨端业务链（仍是 UI+API）   → 22
UX  专家 CONS/UX/VIS 打分        → 26（与联测并列强制）
```

同一业务（如「创建商品草稿」）：R1 有 API 条，端页必须有 **联测** 条，新页还必须有 **26 UX 走查** 一行结论。

---

## 6. UI/UX 专家检查（与联测并列强制）

新增或大改的**用户可见页面**，除前后端联测外，必须安排 UI/UX 专家按 [26](./26-UX专家走查.md) 走查：

| 组 | 内容 | 不合格 |
|----|------|--------|
| CONS | 主色、顶栏、字号、列表心智、空态/Toast；买家深色顶栏例外 | 均分 &lt;1.5 或 P0/P1 项打 0 |
| UX | 主 CTA、返回、表单错误、防连点、状态色、触控、切店 | 同上 |
| VIS | 一屏一任务、栅格、对比度、无紫光堆砌、对齐 PRD 线框 | 同上 |

**输出**：每页一行 `页面 | CONS均分 | UX均分 | VIS均分 | 阻断项 | 截图 | 结论`。  
**禁止**：只做功能联测、跳过 UX 走查就宣称可交付。
