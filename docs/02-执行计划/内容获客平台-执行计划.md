## 0. 执行规则（必须遵守）

### 0.1 一步一验

1. **只允许顺序执行** Step；不得跳过、不得「先做后面再补前面」。
2. 每个 Step 完成必须同时满足：
   - **专项验收**（该 Step 表格内用例）全部 PASS
   - **阶段回归门禁**（§0.3）PASS
3. 任一 FAIL → **停止**，修复后从该 Step 重跑；禁止带缺陷进入下一步。
4. **禁止**在未写验收脚本的情况下口头宣称「已完成」；脚本未建 → 状态只能是 🔄，不能 ✅。
5. **提测前必须通过代码 QC**（[代码QC计划](./内容获客平台-代码QC计划.md) L0+L2；批次出口 L3），否则 QA 可退回。

### 0.2 状态标记

| 标记 | 含义 |
|------|------|
| ⬜ | 未开始 |
| 🔄 | 进行中 / 部分交付 |
| ✅ | 本 Step **专项 + 回归**均 PASS，且有脚本/清单证据 |
| ⏸ | 被外部依赖阻塞（须在阻塞登记表写原因与解除条件） |
| — | 本 Phase 不做 / 可选后置 |

### 0.3 每步回归门禁（固定）

```bash
cd apps/api
# 主产品不回归破坏
python tests/run_m0_m8.py
# 商城：已验收批次串联（随进度加长）
python tests/run_shop_all.py --through <当前批次>
# Alembic head 与 EXPECTED_HEAD 一致
python -c "from tests.alembic_head import EXPECTED_HEAD; print(EXPECTED_HEAD)"
```

| 编号 | 通过标准 |
|------|----------|
| RG-1 | `run_m0_m8.py` 退出码 0（主产品基线） |
| RG-2 | `run_shop_all.py --through <本批次>` 退出码 0 |
| RG-3 | `alembic_head.py` 的 `EXPECTED_HEAD` = 本批次声明的迁移号 |
| RG-4 | 本批次涉及 Web 路由时：`apps/web` 对应 Vue 文件存在且路由可解析（脚本 `check_files` 或手工清单勾选） |

> LLM / Agent 不稳定时：`VERIFY_SKIP_AGENT=1` 可跳过 Agent 子集；**不得**跳过 `verify_shop_m*`。

### 0.4c 原型对照与提验纪律（强制）

1. **开发前必读 PRD 锚点**（列表 / 详情 / 新增 / 编辑 / 审批各自锚点）；未对照不得宣称按原型。  
2. **业务/流程/栏位规格对照线框**：  
   - 列表：默认列不得少、高级筛选、导出、列设置、可选每页条数、行操作矩阵；  
   - **详情 / 新增 / 编辑 / 审批**：PRD 栏位与必填/显隐/校验不得擅自减少；**展示名须与 PRD 原文一致**；附件可传或可预览；未做 Tab/字段须登记缺口。  
   **禁止**把线框视觉当验收标准。  
3. **UI 皮必须跟现网**：布局壳、Element Plus、主色与 CRM 同类页习惯。  
4. **已开发多少 · 测试完成多少**：本批已落地须测完对应用例；禁止冒烟顶全量。  
5. **提请用户验收前**：自测 + 业务/栏位对照 + 用例 ID；未过不得提验。  
6. **资质/附件**：真实选文件 → `file_id` → 再 OCR；审核/详情须可预览。  

细则见 `.cursor/rules/prototype-acceptance-discipline.mdc`（§0 / §0b / **§0c**）。

### 0.4b 自动化跟批策略（强制 · 禁止「全部做完再重写」· 禁止测不全）

> **用例文档先冻结，自动化随开发启用。已提交的功能范围 = 必须测完的用例范围。**

| 原则 | 说明 |
|------|------|
| **文档先定** | QA 库六段式 / FE-* / 端页 ID 为权威；开发与脚本跟文档，不另起用例体系 |
| **实现一块、测试一块** | 代码可点/API 已合入 → 当日或本批内完成对应用例（脚本或登记的手工联测记录）；**禁止欠测交付** |
| **实现一块、自动化跟一块** | 去掉本批相关 `@pytest.mark.skip`，按**已有用例 ID**补真断言；冒烟可作门禁子集，**不能替代** FE-* / 端页写操作 |
| **禁止整包重生** | 除非路由/契约相对文档大改；改则同步改脚本 **并回改 QA 文档**，禁止静默分叉 |
| **R1 API** | 本批次 `verify_shop_mN.py` 须绿；未实现接口只允许显式 SKIP + 登记，不得冒充 Pass |
| **联测 / Playwright** | 页面可点后：**必须**启用对应该页的 FE-* / 20·20b·21；仅当环境 Blocked 才允许「仅手工联测至某日」书面登记 |
| **UX（26）** | 新页首次可点即走查；不依赖「开发完再生成脚本」 |
| **全 Phase 末** | `run_shop_all` 全轮可跑 + [开箱标准](./内容获客商城-开箱即用交付标准.md)，是收口不是重写起点 |

**每批次 ✅ 时自动化检查清单**：

1. 本批 `verify_shop_mN.py`：本批范围断言无不应有的 skip；ID 与 QA 库一致（或文件头有对照表）  
2. 本批新增/改动**写操作页**：FE-* / 端页联测已 Pass（脚本或有日期的手工 Network 记录），禁止只留「页能打开」  
3. Playwright：本批可点页去掉 skip 或书面 Blocked；断言跟用例步骤，禁止空断言  
4. `run_shop_all.py --through <本批>` 退出码 0（允许登记内的预期 skip，禁止静默挂绿）  
5. 回复/验收单列出：**本批交付清单 ↔ 已测用例 ID ↔ 结果**

### 0.6 Definition of Done（批次级）

某批次标 ✅ 当且仅当：

1. 范围表内 API/库表/权限全部落地  
2. `verify_shop_mN.py` 全绿（含负向；本批范围无不应有的 skip）— 遵循 **§0.4b**  
3. `run_shop_all.py --through mN` 退出码 0  
4. 本批次页面：有最小可用 UI **且** 对应 FE-*/端页联测 Pass（冒烟不算），或明确「仅 API，UI 并入下一批」并登记（挡开箱演示）

6. Playwright：本批可点页面对应用例已去 skip 并含真断言，或书面 Blocked  
7. **交付清单 ↔ 已测用例 ID** 已列出且无欠测项（§0.4b/0.4c）  
8. PRD §8.13 / §9.1 / 功能清单状态列已同步  
9. 无未关闭的 P0 缺陷（权限穿透、双开权益、可跳过合规闸）
