## 1. 你要的最终形态（一句话）

> 本机（或约定测试机）按 **一份启动说明** 起服务 → 用 **固定演示账号** 登录 → 平台 / 商家 / 买家三条链路都能点通 → 按 **演示剧本** 15～30 分钟讲完「入驻→上架→付钱→履约→退款→（Mock）公域」→ 过程中不出现 P0/P1 级故障。

**「不需要再做什么」** 的含义：

| 你不用做 | 交付必须已做好 |
|----------|----------------|
| 手写 SQL / 手工造商家商品订单 | 一键种子：账号+多状态商家+店铺+商品+订单+权益 |
| 猜哪个号能登、密码是什么 | 《演示账号表》打印在启动说明里 |
| 自己对接微信/抖店才能演示 | 默认 **Mock**；真机为加分项，不阻塞签收 |
| 问研发「这个按钮能不能点」 | 验收报告签收 + 已知问题表为空（或仅 P3） |
| 再装一堆神秘依赖 | 启动说明 ≤ 10 步，失败有排查 |

### 2.2 开箱门槛（交付专属 · 本文件）

| ID | 必须 | 验收方式 |
|----|------|----------|

## 3. 启动说明（交付物必须提供的文件）

交付时仓库内须有且保持有效：

| 文件（约定路径） | 内容 |
|------------------|------|
| `docs/04-运维与手册/内容获客商城-本地演示启动.md` | 端口、命令、常见失败 |

1. API health 返回 ok  
2. Web `5173` 能开登录页  
3. 买家端约定入口能开（H5 `5174` 或说明中的小程序路径）  
4. 用 §4 账号登录无报错

## 5. 演示数据最小集（种子必须覆盖）

| 数据 | 最小数量 / 状态 | 用途 |
|------|-----------------|------|
| 商家 | ≥1 active 经营中 + 1 审核中 + 1 未入驻 + 1 暂停或清退 | 状态机演示 |
| 店铺 | 经营中商家 ≥1 店（建议 2 店示多店） | 切店、已购店名 |
| 套餐 | P10 上架 basic（及可选 flagship/加购）；经营中商家已开通 | A18 / P11 |
| 商品 | 课/资料/服务各 ≥1 **on_sale**；另 1 条 draft 或驳回样例 | 上架闸 |
| 订单 | ≥1 paid + 可选 1 待付 | 订单列表 |
| 权益 | ≥1 active（课） | 学课 |
| 退款样例 | 可选 1 条已退（或剧本里现退） | H3 |
| 公域 Mock | 1 条可领权 token **或** 一键触发 Mock 单的说明 | Mx Mock |
| 结算 | 可选 1 条 pending 批次（P05 交付后） | 财务演示 |

种子原则：**幂等**、前缀 `演示`/`QA_DEMO_`、可 `--reset` 重建、不依赖你本机残留点击数据。

## 6. 标准演示剧本（你独立可跟做 · 约 20 分钟）

| 步 | 谁 | 动作 | 成功画面 |
|----|-----|------|----------|
| 1 | 平台 | 超管登录 → P02 看到多种商家状态 | 列表分列入驻/套餐状态 |
| 2 | 平台 | 打开「审核中」→ P03 通过或展示样例已通过商 | 有 merchant |
| 3 | 商家 | 经营中账号进 `/shop` | A01 看板有数 |
| 4 | 商家 | A02 看已上架三类商品；可选演示一条驳回不可售 | 合规闸 |
| 5 | 买家 | 进店 → 下单 → **Mock 支付成功** | 已购出现 |
| 6 | 买家 | 学课或领资料/看核销码（择一） | 履约成功 |
| 7 | 买家或商家 | 全额退款 | 不可再学 |
| 8 | 平台或商家 | （可选）Mock 公域领权 M14 | 领权后进已购 |
| 9 | 平台 | P11 展示订阅 / A18 商家看权益 | 套餐可读 |

**演示失败判定**：任一步因缺陷无法继续且无剧本备选路径 → **未达交付**，退回修。
