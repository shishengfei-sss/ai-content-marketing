# 文档组织规范

> **适用范围**：本仓库（智营获客）及由此模板衍生的新项目。  
> **权威源**：本文档；Cursor 自动遵循 [`.cursor/rules/docs-organization.mdc`](../../.cursor/rules/docs-organization.mdc)。

---

## 一、核心原则

| 原则 | 说明 |
|------|------|
| **文档归 `docs/`** | 方案、PRD、手册、测试、归档等一律在 `docs/` 内，**禁止**在仓库根目录散落 `.md` / `.html` / `.pdf` |
| **一级目录必须编号** | `docs/` 下每个一级文件夹为 `NN-名称`（两位数字 + 连字符） |
| **不删除只归档** | 过时、被取代、无关内容移入 `docs/06-归档/`，禁止 `git rm` 文档（除非用户明确要求） |
| **索引同步** | 新增/移动后更新对应 `README.md` 及 `docs/README.md` |
| **链接用完整路径** | 跨目录引用带 `docs/` 子目录名；代码注释同理 |
| **优先中文命名** | `docs/` 内子目录与交付文件名默认中文；技术目录 `_shared/`、`assets/` 等可保留英文 |

## 二、仓库根目录

根目录只保留**可运行代码**与**入口文件**：

```
<项目根>/
├── README.md                 # 仓库总导航（必须维护）
├── apps/                     # 应用代码（api / web / mp）
├── packages/                 # 共享包
├── scripts/                  # 部署、运维脚本
├── docs/                     # 全部文档（见第三节）
└── project-docs-index/       # 浏览器文档总索引（可选）
```

**禁止**在根目录新建：`prd-packages/`、`_archive/`、`测试用例/`、`自动化测试/`、`user-manual/` 等文档目录（已迁入 `docs/`）。

## 四、各目录细则

### 4.1 `01-PRD/`

- Markdown PRD 与 HTML 模块包**同级存放**（根目录 `.md`/`.html` 不加编号）。
- **HTML 模块包子目录必须编号**：`docs/01-PRD/NN-<中文模块名>/`（两位序号 + 连字符 + **中文主题名**；可保留 `-prd`、`-phase1` 等后缀）。
- 编号按**版本/功能时间线**递增；完整清单见 [`01-PRD/README.md`](../01-PRD/README.md)。
- 新 HTML 模块 → 取下一个序号（当前最大 `21`），更新 `01-PRD/README.md` 与全库链接。
- 与 `02-执行计划/` 互链；执行计划引用 PRD 用 `../01-PRD/NN-<中文模块名>/`。
- **模板 B 操作页**（模块 21+）：页面文件用中文名，如 `06-平台端UI.html`；入口仍为 `index.html`。
- **写作与 HTML 体例**：见 [`PRD写作规范.md`](./PRD写作规范.md)（Markdown 元信息/章节编号；HTML 模板 A Trae 单页 01～20 / 模板 B 多页交互 21+）。

### 4.2 `02-执行计划/`

- 版本线计划：`v<版本>-<主题>执行计划.md`（例：`v1.7-xxx执行计划.md`）；版本号段可含英文缩写（`crm`、`agent`）。
- 独立专题计划：可用**中文主题名**，如 `内容获客平台-执行计划.md`。
- 专题 HTML 包：子目录中文，如 `支付抖音启动计划/支付抖音启动-执行计划.html`。
- 新版本必须更新 [`00-总览/版本交付线梳理.md`](./版本交付线梳理.md)。

### 4.3 `05-测试与验收/`

```
├── 验收报告/  # 验收报告
└── 自动化报告/   # 自动化报告
```

## 五、命名约定

### 5.1 通用原则

| 原则 | 说明 |
|------|------|
| **默认中文** | `docs/` 内新建子目录、对外交付文件、PRD 模块名优先中文 |
| **必须编号** | 一级目录 `NN-`、PRD 模块包 `NN-`、归档子目录 `NN-` |
| **批量改链** | 重命名/移动后须更新 `docs/`、`project-docs-index/`、`scripts/`、代码注释中的路径 |
| **技术例外** | `_shared/`、`assets/`、`hljs/`、第三方 `.min.js` 保留英文 |

### 5.2 各目录格式

| 类型 | 格式 | 示例 |
|------|------|------|
| 执行计划（版本线） | `vX.x-<主题>执行计划.md` | `v1.3-招标线索与CPQ执行计划.md` |
| 执行计划（专题） | `<中文主题>-执行计划.md` 或 `.html` | `内容获客平台-执行计划.md` |
| 执行计划 HTML 包 | `02-执行计划/<中文主题>/` | `支付抖音启动计划/` |
| 整合 PRD | `PRD-<产品名>-<范围>.md` | `PRD-智营获客-整合v1.3.md` |
| 模块 PRD Markdown | 模块目录内 | `21-内容获客商城-phase1/PRD-内容获客商城-phase1.md` |
| HTML 模块包目录 | `NN-<中文模块名>/` | `07-成交增强-prd/`、`21-内容获客商城-phase1/` |
| HTML 模块主文件 | 中文主题名 + 后缀 | `成交增强-prd.html`、`06-平台端UI.html` |
| 多页 PRD 入口 | `index.html` | 保留英文（链接枢纽） |
| 测试子目录 | 中文 | `自动化测试/`、`测试用例/`、`验收报告/`、`自动化报告/` |
| 对外资料 | 中文文件名 | `用户操作手册.html`、`抖音卖课实战指南.html` |
| 汇报材料 | `07-对外资料/03-汇报材料/` | pptx / html / pdf / md 提纲 |
| 归档一级子目录 | `NN-<名称>/` | `01-早期总体方案/` |

### 5.3 可保留英文的例外

| 项 | 说明 |
|----|------|
| `_shared/`、`assets/` | Trae/HTML 包内硬编码相对路径 |
| `echarts.min.js`、`mermaid.min.js` 等 | 第三方库文件名 |
| `index.html` | 多页 PRD 标准入口 |
| 版本号前缀 | `v0.5-crm`、`v1.6-ai销售经理` 等惯例 |
| `-prd`、`-phase1` 后缀 | 模块目录/文件名中可保留 |
| `06-归档/` 历史包 | 已归档英文目录低优先级改动；**新增**归档仍建议中文 |

批量重命名工具：`scripts/rename-docs-chinese.py`（改映射表后复用）。

### 9.5 HTML 操作页原型（新项目强制）

凡采用 **模板 B**（多端 / 多屏 / `index.html` 多页交互）的新项目或新 PRD 模块，**必须**执行 [`PRD写作规范.md` §2.5](./PRD写作规范.md#25-操作页原型走查规范p02-金标准)：

| 项 | 要求 |
|----|------|
| 金标准样例 | 从本仓库复制或链到 `01-PRD/21-内容获客商城-phase1/06-平台端UI.html#p02` 作对照 |
| 操作页交付 | 七层骨架 + 列表五件套 + **四张规格表**（状态矩阵 · 点击校验 · UI 线框覆盖 · **下拉/选择规格** §2.5.9） |
| 线框内/外 | 线框内仅用户文案；权限码、字段名、API 放线框外 |
| 验收 | 走查前勾选 §2.5.7 自检清单；PRD Markdown §7 与 HTML 双向一致 |

**模板 A**（Trae 单页、&lt;10 屏）不强制 §2.5 全套，但新增操作仍建议补「点击校验」表。  
**改版旧模块**（01～20）不强制 retro-fit，除非用户明确要求对齐金标准。
