## 一、Markdown PRD 体例

### 1.1 两类 PRD

| 类型 | 命名 | 位置 | 用途 |
|------|------|------|------|
| **整合 PRD** | `PRD-智营获客-<范围>vX.x.md` | `docs/01-PRD/` 根目录 | 跨版本总览、主产品权威源 |
| **模块 PRD** | `PRD-<中文模块名>-phaseN.md` 或模块内同名 | `docs/01-PRD/NN-<中文模块名>/` | 单模块/产品线增量需求 |

### 1.2 元信息块（文件开头，必填）

```markdown
# 智营获客 · <模块名> 产品需求文档（PRD）vX.x

> 文档基线：vX.x（Alembic NNN，若已立项）｜状态：📋 规划 / ✅ 已交付 / 🚧 开发中｜更新日期：YYYY-MM-DD
> 配套可视化：[index.html](./index.html) 或 [module-prd.html](./module-prd.html)
> 执行计划：[../02-执行计划/xxx执行计划.md](../02-执行计划/xxx执行计划.md)
> 来源：<SRS / 方案摘要 / 上级 PRD 链接>
> 状态图例：✅ 本版交付｜⏳ 后续 Phase｜🚫 本版不做
```

模块 PRD 若尚未立项，Alembic 可写「待立项」；状态图例可省略。

### 1.3 章节编号

- **一级章节**：`## 一、` `## 二、` … 中文序号（与整合 PRD、AI 销售经理 PRD 一致）
- **二级章节**：`### 1.1` 或 `### 2.1` 阿拉伯数字（沿用现有惯例）
- **禁止**：模块 PRD 单独使用 `## 1.` 作为一级标题（与整合 PRD 割裂）

### 1.4 推荐章节骨架（模块 PRD）

1. **一、产品概述与目标**（或「目标与边界」）— 定位、Phase 做/不做
2. **二、角色与权限**（或并入业务域章节）
3. **三、核心业务域** — 状态机、数据模型、关键流程
4. **四、合规 / 非功能**（若有）
5. **五、页面与 API 清单** — 链到 HTML 线框
6. **六、关联文档** — 执行计划、功能清单、方案摘要

### 1.5 交叉引用

- 链执行计划：`../02-执行计划/vX.x-xxx执行计划.md`
- 链方案摘要：`../00-总览/xxx.md`
- 链 HTML UI：`./index.html` 或 `./NN-xxx.html#anchor`
- 代码注释中的文档路径须含完整子目录

## 二、HTML 可视化包体例

仓库内存在 **两套模板**，按模块复杂度选用，**不强制 retro-fit 旧模块**。

### 2.1 模板 A · Trae 单页文档（旧标准，01～20）

**适用**：单模块 CRM/创作增强、Gap 分析、字段级增量。

| 项 | 约定 |
|----|------|
| 主文件 | `NN-<中文模块名>/<中文主题名>.html` 单文件（如 `成交增强-prd.html`） |
| 生成标记 | `<!-- Generated by Trae Work -->`（可选保留） |
| 字体 | InstrumentSans / GeistMono（`./_shared/fonts/`，若缺失则回退系统字体） |
| 结构 | 封面 → 章节导航 → `.ui-wire` 线框 |
| 主色 | `--accent: #1677ff` |

**代表**：`07-成交增强-prd/`、`15-产品主数据UI交互/`

### 2.2 模板 B · 多页交互线框（新标准，21+）

**适用**：多端（平台 / 商家 Web / 买家小程序）、页面数 >15、需 Tab 切换演示的复杂产品线。

| 项 | 约定 |
|----|------|
| 入口 | **`index.html`**（权威入口；中文快捷名如 `【点我看UI】*.html` 仅作跳转别名） |
| 子页 | 按职责拆分：`01-管理端UI.html`、`02-买家端UI.html`、`03-数据流.html`、`04-数据模型.html`、`05-角色权限.html`、`06-平台端UI.html` |
| 兼容别名 | `<模块名>.html` → `meta refresh` 跳转 `index.html` |
| 设计 token | **必须**对齐 `packages/shared/design-tokens.css`（`#1677ff`、`--header-height: 56px` 等） |
| Web 壳 | 顶栏对标 `AppLayout`；侧栏宽约 200px；Element Plus 风格标签/按钮 |
| 买家端 | 可用独立视觉（如小程序深色顶栏 `#0A1628`），须在 README 注明「买家端独立规范」 |
| **线框内/外** | 线框内仅用户可见文案；落库字段、权限码等放线框外。完整走查规范见 [§2.5 操作页原型走查规范（P02 金标准）](#25-操作页原型走查规范p02-金标准) |

**代表**：`21-内容获客商城-phase1/`

### 2.3 选型决策树

```
新 HTML PRD 包
  ├─ 单端、<10 屏、以文字规格为主 → 模板 A（Trae 单页）
  └─ 多端 / >15 屏 / 需可点击走查 → 模板 B（多页 + index.html）
```

### 2.4 共同要求

- 目录名：`docs/01-PRD/NN-<中文模块名>/`（两位序号 + 中文主题名；可保留 `-prd`、`-phase1` 后缀）
- 技术子目录 `_shared/`、`assets/` 保留英文（见 [文档组织规范 §5.3](./文档组织规范.md#53-可保留英文的例外)）
- 新增模块取下一序号，更新 `01-PRD/README.md` 与 `project-docs-index`
- 主色与 Web 产品一致：`#1677ff`（见 `design-tokens.css`）
- 权限命名：`<域>.<资源>.<动作>`，与 `apps/api/app/permissions.py` 风格一致（如 `crm.lead.list_own`、`shop.product.publish`、`platform.shop.plan.manage`）

### 2.5 操作页原型走查规范（P02 金标准）

> **权威样例**：[06-平台端UI.html#p02](../01-PRD/21-内容获客商城-phase1/06-平台端UI.html#p02) · PRD [§7.0](../01-PRD/21-内容获客商城-phase1/PRD-内容获客商城-phase1.md#70-操作页线框规范原型走查)

模板 B 中，凡含**列表 + 行内操作 + 抽屉/弹窗/详情 Tab** 的操作页，须按 **P02 商家租户** 的七层结构与三张规格表交付。新模块 HTML 与改版时，以 P02 为对照自检。

#### 2.5.1 页面七层骨架

| 层级 | 元素 | 类名 / 约定 | 必填 |
|------|------|-------------|------|
| L1 | 标题 + 优先级 | `H2` + `tag-r`（P0）/ `tag-b`（P1） | 是 |
| L2 | 业务语境 | `.note.note-b`「**先记住两句话**」— 复杂域概念用 2 句白话 | 有歧义时必填 |
| L3 | 权限摘要 | `.sub` 链到 `05-角色权限.html#perm-*` | 是 |
| L4 | 子页 Tab | `.pdoc-tabs` + `.pdoc-panel`；锚点 `#p02a` 可直链 | 有子屏时必填 |
| L5 | 线框区 | `.shell` / `.crm-toolbar` / `.wf-form` / 样例表 | 是 |
| L6 | 规格表 | 见 §2.5.3 三张表 | 是 |
| L7 | 链路小结 | `.op`「操作链路小结」— 跨页路径 | 有跨页时必填 |

#### 2.5.2 线框内 / 线框外（与 §7.0 一致）

| 区域 | 放什么 | 禁止 |
|------|--------|------|
| **线框内**（`.shell`、`.wf-form`、`.phone` 内） | 标签、placeholder、按钮、页脚引导、用户可见状态 badge | 权限码、表字段名、页码（P02-A）、绿色「预填自…」技术角标 |
| **线框外** | `.op`、`.note`、`table.meta`、点击校验表、字段映射、API 路径 | 把研发注解塞进输入框 placeholder |

**操作列文案**：面向运营/商家展示中文（「详情」「处理续费」），不写内部页码或 ID。

#### 2.5.3 四张规格表（操作页必备）

1. **状态 × 操作矩阵**（`table.meta.matrix`）  
   列：`状态` · `行内操作` · `落点页面/抽屉` · `权限`（链权限码）

2. **点击校验**（标题含「前端显隐 + API 二次校验」）  
   列：`操作` · `前置校验`（①②③ 编号 + 权限链） · `失败提示`（**toast 原文**） · `成功落点`（页码 + 锚点）

3. **操作按钮 · UI 线框覆盖**  
   列：`操作` · `触发位置`（顶栏/行内/摘要区） · `UI 线框`（子页锚点） · `点击校验`（指向上表行）

4. **下拉/选择规格**（`table.meta.matrix`，标题「下拉/选择规格」）— 见 [§2.5.9](#259-下拉与选择控件规格)  
   列：`控件` · `单选/多选` · `枚举 / 来源` · `取值逻辑` · `落库 / API`

规则摘要：无权限 → 按钮不渲染；状态不符 → 禁用/隐藏；提交 API 再验，失败 toast 原文案。

#### 2.5.4 列表页五件套（对齐 CRM）

| 能力 | 原型要求 |
|------|----------|
| 快捷 Tab | 视图切换 + 计数 badge；与看板指标卡下钻联动 |
| 工具栏 | `.crm-toolbar`：搜索 + 高频筛选 +「高级筛选」+ 列设置 + 主 CTA |
| 高级筛选 | **至少画一次展开态**（蓝底面板 + 查询/重置） |
| 样例表 | **≥5 行**，覆盖全部入驻/审核/套餐等状态；边界态用行底色（浅黄/浅灰） |
| 分页 | `共 N 条` + 每页 `10/20/50/100` 下拉 + 翻页按钮 |

表头可排序列标 `↕`；列设置可选列在线框外 `.op` 说明。

#### 2.5.5 子页面命名与 Tab 规则

| 类型 | 命名 | 示例 |
|------|------|------|
| 主列表 | `P02` | 商家列表 `#p02-list` |
| 抽屉/弹窗 | `P02-A` … `P02-E` | 发起入驻、暂停、恢复 |
| 详情 Tab | `P02-B-{name}` | 概览、当前权益、服务记录 |
| 详情子抽屉 | `P02-B-R` / `P02-B-N` | 申请续费、写跟进 |
| 校验专节 | `P02-B-service-validation` | 可并入 Tab 或独立锚点 |

- 子页用 **顶栏 Tab** 切换，避免纵向堆叠过长页。
- **详情顶栏**仅展示实体信息 + 二级 Tab，**不设**与列表重复的写操作（如暂停/开通订阅放列表行内或摘要区）。
- 详情内嵌列表：默认每页 20、筛选后回第 1 页。

#### 2.5.6 表单变体（主体类型 / 多端）

- 同一抽屉内切换变体：**并排展示** 2～3 种主体线框（个人/个体/企业），标注「当前选中」。
- 附 **栏位显隐矩阵表**（栏位 × 主体类型，必填/可选/—）。
- 敏感字段默认脱敏，👁 揭露须权限 + 审计（线框外说明）。

#### 2.5.7 走查自检清单

新增或改版操作页 HTML 时逐项勾选：

- [ ] L1–L7 七层齐全（L2/L4/L7 按适用性）
- [ ] 线框内无技术字段名 / 权限码
- [ ] 列表五件套 + 全状态样例行
- [ ] 四张规格表完整（含**下拉/选择规格**，§2.5.9）
- [ ] 权限码链到 `05-角色权限.html#perm-*`
- [ ] 子页 Tab + 锚点可直链（`index.html` 入口可跳）
- [ ] 跨页操作在 `.op` 链路小结中写清路径
- [ ] PRD §7 对应节与 HTML 双向一致
- [ ] **下拉/选择规格表**完整（§2.5.9，含**级联**列）；已链 `04-数据模型#select-cascade`

**买家端小程序**（`02-买家端UI.html`）：可用 `.phone` 壳与独立配色；仍须点击校验表 + 状态矩阵 + **下拉/选择规格表**，列表规范可简化为卡片 + 底栏（无 CRM 列设置）。

#### 2.5.8 新项目与跨仓库执行（强制）

| 场景 | 是否执行 §2.5 |
|------|----------------|
| **新项目** + 模板 B（多端 / `index.html` 多页） | **强制** — 从立项首版 HTML 起按 P02 金标准 |
| 本仓库新增 `01-PRD/22+` 模块 B | **强制** |
| 模板 A（Trae 单页、&lt;10 屏） | 不强制全套；有关键操作时仍建议「点击校验」表 + 下拉规格 |
| 旧模块 01～20 存量 | 不强制 retro-fit，除非改版或用户明确要求 |

**新项目初始化**须将本文档（含 §2.5）一并拷入 `docs/00-总览/`，见 [文档组织规范 §9](./文档组织规范.md#95-html-操作页原型新项目强制)。

**金标准 HTML 样例**（可链引用，不必整包复制）：`docs/01-PRD/21-内容获客商城-phase1/06-平台端UI.html#p02`。

#### 2.5.9 下拉与选择控件规格

凡线框中出现**下拉、单选组、可搜索选择器、Tab 式视图切换**（用户感知为「选一个」或「选多个」），须在**线框外**补 **下拉/选择规格表**（可与点击校验表并列，置于该页/抽屉/弹窗规格区末尾）。

| 列 | 必填内容 |
|----|----------|
| **控件** | 位置 + 标签（如「P02 列表 · 入驻状态」「A03 表单 · 关联专栏」） |
| **单选/多选** | 明确写 **单选** 或 **多选**；Tab/分段按钮视图为单选 |
| **枚举 / 来源** | 固定枚举写全量值（`active`/`suspended`/…）；动态项写数据来源表/API |
| **取值逻辑** | 过滤条件、默认项、与权限/状态联动、空态文案 |
| **级联** | **必填**：`—`（无）或 `是：父→子` / `否：…`；说明父项变更是否清空/刷新子项、或仅显隐栏位 |
| **落库 / API** | 字段名、Query 参数或请求体键；只读控件写「—」 |

**书写规则**：

- **线框内**下拉仅展示用户可见文案（如 `王管家 ▾`），**禁止**在线框内写「单选」「来源 P10」。
- **全站通用**枚举（分页条数、主体类型、入驻状态等）在 [`04-数据模型.html#select-spec`](../01-PRD/21-内容获客商城-phase1/04-数据模型.html#select-spec) 维护一份权威清单；各页表可写「同 [04 §通用](./04-数据模型.html#select-common)」并只列本页**增量**控件。
- **搜索型下拉**（选 tenant、选商品、选管家）：标明 `GET` 接口、搜索字段、`page_size`、去重规则。
- **级联**（独立列，勿塞进取值逻辑）：`—` 无级联 · `是：A→B` 父变则清空/刷新/显隐子项 · `否：…` 多筛选独立 AND。复杂链路见 [`04-数据模型#select-cascade`](../01-PRD/21-内容获客商城-phase1/04-数据模型.html#select-cascade)。
- 无下拉的操作页（纯只读详情）可省略本表，在 `.op` 注明「本页无选择控件」。
- **多 Tab / 多 `pdoc-panel` 操作页**（如 P02 商家列表含 P02-A～E）：**每个子页 panel 内各放一张规格表**（锚点 `#<panel-id>-select-spec`），只列**当前子页**可见的下拉/选择控件；**禁止**在整组 `article` 末尾汇总全子页控件（否则切 Tab 会看到无关行）。无下拉的子页可写「本页无选择控件」。

**样例**（P02-E 新管家）：单选 · 来源 `GET /admin/platform-users?platform_shop_role=platform_shop_cs&status=enabled` · 仅启用且为商家管家角色的账号 · `account_manager_user_id`。
