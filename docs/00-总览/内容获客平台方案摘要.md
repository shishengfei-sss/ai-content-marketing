## 1. 定位一句话

**AI 内容工厂 + 全域交易闭环 + CRM 持续经营** —— 不只卖课工具，而是帮商家「能生产获客内容 → 能挂四平台成交 → 能进 CRM 跟进」。

对标小鹅通/千聊的**差异化**：竞品卖「店」与履约；我们卖**生产 + 成交 + 运营**完整闭环。

---

## 2. 平台三层架构

| 层 | 职责 | 现状 |
|----|------|------|
| **AI 内容工厂**（生产层） | 营销创作顾问：多平台文案 / 笔记 / 视频脚本；知识库 + 品牌语气 + 合规自检 | ✅ v0.6～v1.1 已交付 |
| **内容获客平台**（交易层） | 商品 / 订单 / 支付 / 权益；四平台挂载；虚拟与服务先闭环 | 🚧 Phase1 开发中（M0 API ✅ · 见执行计划 v2.0） |
| **智营 CRM**（运营层，可选） | 活动 / 线索 / 客户跟进；成交后经营；与商城数据互通 | ✅ 主产品 v0.5～v1.6 |

**公域层**：抖音优先 → 视频号/快手 → 小红书；路径 A（官方店）/ 路径 B（交付履约）并列可选。

## 3. 内容营销智能体 · 分期能力

战略一体、落地分期 —— **不与商城 Phase 1 抢工期**。

| 阶段 | 内容 | 代码版本建议 |
|------|------|--------------|
| **Phase 0** ✅ | 文案 / 笔记 / 视频脚本；创作→活动→CRM | v0.6～v1.6 已交付 |
| **Phase 1** | 商城 MVP：交易闭环；智能体「复用导出」上架 | 商城 PRD Phase1 |
| **Phase 2** | 智能体×商城打通：课纲+详情+卖点一键生成商品 | v1.7 |
| **Phase 3** | AI 商用配图；图文成品 ZIP；素材授权可追溯 | v1.8 |
| **Phase 4** | 短视频半自动：TTS + 商用 BGM + 字幕；人审后导出 | v1.9 |
| **Phase 5** | A/B · 渠道归因 · 发布效果回流 · Multi-Agent | v2.0+ |

**Phase 1 硬边界**：能上架虚拟/服务 → 能付钱 → 能履约；**不写** AI 配图/成片进硬验收。

## 4. 素材合规（图 / 视 / 音）

| 闸 | 要求 |
|----|------|
| **选源闸** | 仅商用授权白名单（图库 / 视频 B-roll / 音乐曲库）；AI 走商用套餐；上传须声明授权 |
| **成片闸** | 每份素材带 license 元数据；未授权不可进入导出包 |
| **发布闸** | 文案合规（已有）+ 素材合规；人审确认后导出；不承诺全自动公域发布 |

分阶段：Phase 3 商用配图 · Phase 4 商用 BGM + 半自动成片。

## 5. 交易合规（挂课 / 挂商品 / 虚拟服务）

**要有，且分两层：** 店内上架是一层，同步公域挂载是更严的一层。与 AI 内容工厂的「文案合规」「素材合规」并列，但**对象不同**——这里审的是**可售卖商品本身**。

| 闸 | 时机 | 检查什么 | Phase 1 |
|----|------|----------|---------|
| **主体资质闸** | 商家入驻内容获客 | 营业执照、ICP、类目资质、支付进件 | P03（平台运营）✅ UI 已有 |
| **商品上架闸** | 商家点「上架」→ `on_sale` | 见下表 | **P0 必做** |
| **公域挂载闸** | 同步抖店 / 课程库 / 挂小黄车 | 通过上架闸 + 公域类目映射 + 平台侧提审 | **P0（Mx 硬验收）** |
| **事后稽查闸** | 举报、抽检、平台通知 | 下架、封禁、审计日志 | P07（P1，可与上架闸共用队列） |

### 5.1 商品上架闸（机审 + 人审）

**机审（复用主产品合规引擎 v0.6，扩展商品字段）：**

- 标题 / 详情 / 卖点 / 课纲摘要：敏感词、夸大承诺、导流外链、违禁类目用语
- 类目与资质匹配（P04 禁入类目、教培需备案材料）
- 结构校验：价格 ≥0、封面、关联内容（课有时长、资料有文件、服务有预约/核销规则）
- 封面图：基础鉴黄/涉政（Phase 1 可规则+抽检；商用图库接入后加强）

**人审（平台运营 `platform.shop.product.review`）：**

- 队列：待审列表 → 通过 / 驳回（须填写原因）
- 驳回后商家仅可改稿重提，不可直接 `on_sale`

**建议状态机（`shop_products.status`）：**

```
draft → pending_review → approved → on_sale
              ↓ rejected（回 draft，保留驳回原因）
on_sale → off_sale（商家下架 / 违规强制下架）
```

私域小程序内测可配置「免人审仅机审」白名单租户；**公域映射与 Mx 首单不允许跳过人审**。

### 5.2 公域挂载闸（比店内更严）

在通过**商品上架闸**之后，同步公域前额外检查：

- 公域类目与店内类目映射是否正确（教培 / 虚拟服务等）
- 链路 ①：抖店商品字段、履约方式与平台一致
- 链路 ②：课程库提审状态（抖音侧审核通过才可挂）
- 挂载文案 / 商品卡是否与审核通过版本一致（防商家过审后私自改价改标题）

未过挂载闸的商品：**可店内卖，不可出现在公域入口**。

### 5.3 与 AI 内容工厂的关系

| 场景 | 审什么 |
|------|--------|
| 营销文案 / 笔记 / 脚本 | 创作顾问合规自检（Phase 0 ✅） |
| 商品详情 / 卖点（v1.7 一键生成） | 生成后进入**商品上架闸**，不自动上架 |
| 封面 / 课内视频 / 推广图 | 素材合规（Phase 3/4）；Phase 1 封面走上架闸机审+人审 |

## 6. 商家 · 店铺 · 套餐（SaaS 扩展）

对标小鹅通：**平台管商家**，**商家开多店**，**店铺挂商品**；套餐可灵活配置，权益按时间段生效。

### 6.1 商家主体类型

| 类型 | 说明 |
|------|------|
| **个人** | 身份证入驻；能力/套餐可受限 |
| **个体工商户** | 执照 + 法人；可对公收款 |
| **企业** | 完整资质 + 对公；全量套餐 |

P03 入驻审核按类型校验材料；与支付进件规则一致。

### 6.2 层级与页面

| 层级 | 实体 | 平台端 |
|------|------|--------|
| 商家 | `shop_merchant_accounts` | P02 管理、P03 入驻审核 |
| 套餐模板 | `shop_subscription_plans` + 功能字典 | **P10 配置** |
| 已购权益 | `shop_merchant_subscriptions`（生效～失效） | **P11 查看/开通/升级** |
| 店铺 | `shop_stores` | P02 下钻；商家 A17 |
| 商品 | `shop_products` | P09 审核 |

### 6.3 订阅、叠加与换档

- 商家可持有 **多条 active 订阅**（主套餐 + 加购包，`purchase_mode=stack`）
- **换档**（basic→flagship）：`purchase_mode=replace`，同 `replace_group` 内旧条 `superseded`
- 单条到期仅重算合并结果；改 P10 模板不影响已购（`plan_snapshot`）

### 6.4 功能字典、合并规则与用量

| 类型 | 示例 | 合并模式（P10 可配） |
|------|------|----------------------|
| 开关 | 抖店、开票 | `any` |
| 存量配额 | 店铺数、商品槽位 | `max` 或 `sum` |
| 周期次数 | 每日提审、每月短信 | `max` 或 `sum` |

有效值 = `merge_entitlements(全部 active snapshot)`。用量计数 tenant 级共享，上限取合并结果（F9）。

**配置与使用**：P10 → P11 → 商家 **A18** 套餐；**A15** 支付；**A19** 单店展示/退款。详见 [PRD §2.5–2.8](../01-PRD/21-内容获客商城-phase1/PRD-内容获客商城-phase1.md)。

## 7. 商城 Phase 1 范围（交易层首期）

**做**：虚拟（专栏/单课/资料包/会员卡）、服务（咨询预约/次数卡/核销）、统一支付与权益、小程序履约、公域订单回流（抖音优先）。

**后移**：店铺装修/H5 商城/实物/门店/四平台齐发（见执行计划与 PPT）。

**永久不做**：多级分销、买家硬映射 Contact、跨商家学员 APP。
