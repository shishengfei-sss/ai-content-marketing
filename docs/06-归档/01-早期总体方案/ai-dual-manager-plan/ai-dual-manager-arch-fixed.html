Tier 1 · Manager Runtime（共享底座，一次构建多实例复用）
编排层

Supervisor 调度

意图识别 / 任务拆分 / 委派 / 汇总。三 Manager 共用同一运行时，仅参数不同。

ReAct 工具调用

子 Agent 通用工具执行层。

Workflow 编排

多步任务状态机，含超时降级（简单问题不调多 Agent）。

护栏执行层（新增 · 独立于 LLM）

PEP · Confirm 闸硬拦截

发邮件/报价/分配/发文/投放/动预算/改工单状态/删知识条目 在工具执行边界强制人审，不依赖模型自觉。

审计留痕

所有增删改 + 每次建议的"结论→依据→工具链"全量留痕。

行级授权

营销只读 / 销售读写 / 服务读写（工单+健康度）由 PEP + CRM 适配器双重强制，杜绝越界。

集成层（新增 · 事件驱动）

EventBus 事件总线

LeadMatured(MQL) / 停滞预警 / 舆情异动 / 退回超时升级 / HealthRiskAlert / RenewalDue / TicketEscalated。协同缝从轮询变订阅。

智能层（向量库统一澄清）

混合 RAG

统一向量库：pgvector 或 Qdrant 二选一并声明（原文档两处冲突），+ 重排。入库即写 embedding。

长期记忆 L0–L4

见下方记忆边界修正，私有空间与共享池显式划分。

可观测平面（新增）

决策追踪 + 评估

采纳率 / 预测准确率 / AI 建议胜率 / 闭环学习回流（结果→归因→重排）。

→

→

→

协同缝 B：销售 → 服务（事件驱动）

销售 客户官成交后触发客户移交
→
EventBus发布 DealClosed 事件 + 客户档案 + 成交备注
→
服务 CSMHealthAgent订阅 → 初始化健康评分 + 启动 onboarding
→
续约/流失事件回流 EventBus → 销售提前介入

协同缝 C：服务 → 销售 / 营销（预警回流）

服务 CSMHealthAgent健康度低于阈值
→
EventBus发布 HealthRiskAlert + 客户画像
→
销售 客户官 + 服务 Supervisor联合制定挽回方案
→
挽回结果回流知识库 → 产品改进反馈
记忆边界修正（原文档独立 vs 共享矛盾）

私有空间（各 Manager 独立）

L0–L4 各自隔离，避免人格混淆与跨域串味。营销/销售/服务各有独立的记忆空间。

共享经验池（脱敏、显式边界）

仅脱敏后的赢单案例/话术/坑/服务解决方案 跨域引用，写入须经策略配置批准。

L0–L4 须就地定义

原文档为黑盒（仅引 v0.4 LM）。本架构要求明确每级含义与生命周期。

相对原始方案的关键修正

  • 新增服务 Manager（P-SVC）：覆盖成交后 → 交付 → 续约/扩展全生命周期，补齐"获客→成单→续约"闭环。含服务官、客户成功官 2 个子 Agent + 6 大服务资料库。
  • 新增护栏执行层 PEP：Confirm 闸从"Prompt 约定"提升为工具执行边界的硬拦截 + 审计 + 行级授权，安全不再寄托于模型自觉。服务域额外覆盖工单状态变更、知识条目删除等操作。
  • 新增EventBus 事件总线：线索 SLA、停滞预警、舆情异动、健康风险预警、续约到期、工单升级改为订阅式，解决原"隐式轮询/靠 CRM 能力悬空"问题。
  • 修正策略配置层：三 Manager 差异（权限/Confirm 触发点/人格/注册表）抽成配置，而非写死在七层 Prompt，可审计、可回归。
  • 修正向量库统一：原文档 pgvector 与 Qdrant 冲突，本图明确二选一并声明职责。
  • 修正记忆边界：独立私有空间 + 显式共享经验池，L0–L4 黑盒须定义。
  • 新增可观测平面：决策追踪链 + 采纳率/胜率评估 + 闭环学习回流，支撑"越用越像资深"。
  • 修正平台化定位：三 Manager 是 Manager Runtime 的前三个插件实例，直接支撑商业篇"AI 管理层矩阵"愿景。
