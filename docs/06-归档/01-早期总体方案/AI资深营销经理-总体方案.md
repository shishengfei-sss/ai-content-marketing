# AI 资深营销经理 · 总体方案与实施规划

> 文档版本：v1.0-plan｜创建：2026-07-21｜关联系统：智营获客（v0.3.3 MVP + v0.4 Agent + v0.6 顾问 + v1.2 报表 + 营销/线索/CPQ 三库 + v1.6 AI 销售经理）
>
> 一句话定位：**AI 资深营销经理 = 营销经理的数字分身 / 全盘营销管理中枢**。它不是一个"写文案的机器人"，而是一个能替营销经理"定策略、做规划、抓线索、写内容、管活动、看数据、带团队"的 Supervisor 智能体。底层复用现有 Agent 框架，外层编排营销库 + CRM + 增长工具链。

---

## 〇、与现有系统的关系（先说结论，避免重复造轮子）

本项目已有资产足以支撑"AI 营销经理"，**无须从零搭建**——尤其 v1.6 的 AI 销售经理已经把最难的"大脑骨架"做出来了，营销经理直接上车：

| 已有能力 | 位置 | 本方案中怎么用 |
|---|---|---|
| 多 Agent Supervisor 调度 | v0.4 Agent C5 | **直接作为"营销经理大脑"的编排骨架** |
| 子 Agent 注册表机制 | v1.6 FR-SALES-MGR-07 | 新增营销子 Agent 仅登记，不改调度核心 |
| ReAct 工具调用 / 长期记忆 L0–L4 | v0.4 Agent B/LM | 子 Agent 工具执行与跨会话记忆 |
| 工作流 + Compliance + Confirm 闸 | v0.4 Agent C1–C3 | **AI 不能擅自发文/投放/发预算**（沿用 BR-01） |
| 混合 RAG（pgvector + 重排） | v0.4 Agent C4 | 营销库检索的事实来源与溯源 |
| 营销创作顾问 | v0.6 Advisor | 直接复用为"内容官 Agent" |
| 营销资料库（全开源私有化） | 营销资料库搭建整体方案 | **营销经理的核心知识底座**，内容官/活动官直接取用 |
| 经营报表与预警 | v1.2 CRM 运营报表 | "洞察官"的数据底 |
| CRM 适配器解耦 | v1.6 D7 / FR-11 | 营销与销售共用底座，可对接第三方 CRM |
| 人格库 | 人格库设计手册 | 塑造"营销经理人格" + 对客/对媒体沟通风格 |
| AI 销售经理（v1.6） | PRD-智营获客-AI销售经理-v1.6 | **并列的另一个 Supervisor**，通过"线索 SLA"协同 |

**结论**：本方案 = 营销经理版 Supervisor（营销人格 + 调度）+ 8 个营销职能子 Agent + 营销库/增长工具链 + 复用三库与 Confirm 闸。增量集中在"营销职责域拆解、营销专属库、职能提示词、主动闭环"，基建全部复用。

> **与销售经理的关系（重要架构判断）**：AI 营销经理与 AI 销售经理是**两个并列的 Supervisor，共享同一套底座（框架/人格库/三库/Confirm 闸/CRM 适配器）**，但职责域与数据侧重不同。两者通过"线索交接 SLA"协同——**营销产生 MQL → 培育 → 移交销售（SQL）**。不做成一个大杂烩，避免意图路由混乱与权限边界模糊。

## 一、界定范围：资深营销经理到底做什么（职责全景）

先把"做营销经理所有工作"拆成 **10 大职责域、约 30 项具体工作**。这是产品规格，也是子 Agent 划分依据。

| # | 职责域 | 具体工作项 | 对应子 Agent |
|---|---|---|---|
| 1 | **市场战略与规划** | 市场/品牌定位；年度/季度营销计划；目标拆解；预算分配与管控；KPI 设定 | 策略官 + Supervisor |
| 2 | **品牌管理** | 品牌定位/资产；品牌 TONE 与话术；VI 一致性；品牌健康度监测 | 品牌官 |
| 3 | **内容营销** | 内容策略/选题；文案/白皮书/案例/短视频脚本；内容日历与排期 | 内容官 |
| 4 | **活动与整合营销** | 活动策划、执行 SOP、展会/路演/线上活动；活动效果复盘 | 活动官 |
| 5 | **数字营销与获客** | SEO/SEM、信息流投放、社媒运营、邮件营销、落地页与转化、线索培育 MQL→SQL | 增长官 |
| 6 | **市场分析与洞察** | 竞品营销打法、市场趋势、营销 ROI/归因、渠道效能、看板问答 | 洞察官 |
| 7 | **公关与传播** | 媒体关系、公关稿、危机公关预案、舆情监测 | 公关官 |
| 8 | **用户运营与增长** | 用户分层、私域/社群、留存与裂变、生命周期营销 | 增长官（协同） |
| 9 | **团队与协同** | 代理商/供应商协同、预算 ROI 汇报、周会/经营会、跨部门（销售/产品）协同 | 协同官 |
| 10 | **内容产出（对内外）** | 给团队的话术/模板/手册；给老板的经营分析报告；对媒体的通稿/口径 | 内容官 + 公关官 |

> 设计判据（沿用销售经理方案）：**凡是"确定性、可审计"的事（预算规则、审批流、发布合规、排期）用规则引擎/工作流打底；凡是"需要判断、生成、解释"的事（策略、创意、复盘、归因）交给 AI 做"建议"，关键动作经 Confirm 闸由人确认。**

## 二、产品形态与用户场景

### 2.1 三类使用者

| 角色 | 怎么用 AI 营销经理 | 典型场景 |
|---|---|---|
| **CMO / 老板** | 看全局、要策略、要 ROI 判断 | "明年预算怎么切？""哪个渠道最值得加投？""品牌声量健康吗？" |
| **营销经理** | 把日常管理工作甩给 AI | "帮我排下 Q3 内容日历""写这周的经营复盘和预警""这个活动复盘一下" |
| **一线营销/内容/投放** | 被 AI 辅助、被提醒、被赋能 | "这个落地页怎么优化转化？""帮我想 3 条信息流文案""竞品最近在打什么？" |

### 2.2 入口与交互范式（复用三端）

- **Web 工作台**：经理视角总控台（策略看板 + 对话 + 内容日历）
- **H5 移动端**：一线随身助理（文案灵感、舆情提醒、活动待办）
- **IM 嵌入（企微/飞书，后续）**：主动推送舆情预警、周报、活动节点提醒
- **交互范式 = 对话式为主 + 主动推送为辅**：AI 不只是"你问它答"，还会在舆情异动、活动 KPI 偏离、预算超支、内容排期空白时主动报警。

## 四、数据地基：营销专属库（决定 AI 能不能"做对事"）

营销经理的能力上限 = 数据 + 知识的质量。营销库（内容素材）已有完整开源方案；但营销经理要"做全局决策"，还缺 5 个专属库。优先级：**先打通已建成的营销库，再分批新建。**

| 库 | 状态 | 内容 | 来源/建设 |
|---|---|---|---|
| 营销资料库 | ✅ 已有方案 | 活动方案、海报、脚本、白皮书、公关稿、话术 | 营销资料库搭建整体方案（MinIO+PG+Qdrant） |
| 竞品营销库 | 🆕 新建 | 竞品打法拆解、战役分析、定价/话术对比 | 从营销库"竞品案例"类目抽离 + 持续采集 |
| 活动效果库 | 🆕 新建 | 活动数据、ROI、转化漏斗、复盘结论 | 接入投放/落地页/CRM 回传，结构化沉淀 |
| 用户分层与画像库 | 🆕 新建 | 人群包、分层触达策略、生命周期阶段 | 对接 CRM 客户 + 私域数据 |
| 舆情与品牌声量库 | 🆕 新建 | 媒体/社媒声量、情感、危机信号 | 合规舆情监测 API（仅公开源） |
| 行业洞察库 | 🆕 新建 | 行业趋势、标杆打法、营销白皮书 | 人工+采集进营销库"洞察"类目 |

> **权限/密级沿用现有 RBAC + 行级过滤**：营销库已有 L1–L4 分级与 AI 账号限制（禁批量导出、密级硬过滤、全审计）。新建库沿用同一套。

## 五、关键设计原则（复用 + 营销延伸）

| 原则 | 做法 | 出处 |
|---|---|---|
| **规则打底，AI 增强** | 预算规则、审批流、发布合规用确定性引擎；AI 只出"建议" | AI 报价调研 + v1.6 |
| **Confirm 闸** | 发文/对外投放/改预算/发布内容，必须经人确认，禁止自动 publish | v0.4 BR-01 |
| **可解释 > 准确率** | ROI、归因、策略都要给"为什么"，否则团队不信任 | v1.6 |
| **防幻觉** | 营销库/竞品库检索结果作为唯一事实来源，强制溯源 | v0.4 C4 |
| **人格一致性** | 稳定营销经理人格 P-MKT + 对客/对媒体镜像沟通 | 人格库手册 |
| **主动而非被动** | 舆情异动、KPI 偏离、预算超支、排期空白主动推 | v1.2 提醒机制延伸 |
| **创意可控** | 文案/创意可批量生成但带"品牌 TONE 校验"，偏离则拦截建议 | 新增（营销特有） |

## 六、分阶段实施路线图

> 依赖链：营销库（已有）是前提；Supervisor 骨架（复用 v1.6 C5）是中枢；营销子 Agent 分批点亮；最后做自治闭环与自进化。

### Phase 0 · 营销数据地基（前提，约 2–3 周）

- **目标**：让 AI"看得见、看得对"营销全貌。
- **核心交付**：营销库 API 对 Agent 开放（沿用营销库方案 §1.4）；新建竞品库/活动效果库表结构与采集管线（轻量起步）；RBAC 行级过滤与 AI 账号权限就位；品牌 TONE 入库为"内容官"校验基准。
- **验收**：Agent 能经授权检索到内容/竞品/活动案例并带溯源。
- **依赖**：营销库方案落地（部分已就绪）。

### Phase 1 · 营销经理人格 + Supervisor 调度骨架（MVP 中枢，约 1–2 周）

- **目标**：先有一个"会调度、有人格、守边界"的营销经理外壳。
- **核心交付**：
  - 在**人格库**新增"营销经理"稳定人格 `P-MKT`（策略感、创意、数据驱动、边界），及"对媒体"镜像变体；
  - 基于 v0.4 **C5 Supervisor** 封装 `MarketingManagerSupervisor`：意图理解 → 任务拆解 → 派发占位子 Agent → 汇总解释；
  - Confirm 闸接入调度（发文/投放/改预算先 propose，人 confirm 才执行）；
  - 与 AI 销售经理共享底座，预留"线索 SLA"协同接口（营销 MQL → 销售 SQL 移交）。
- **验收**：对话能识别"排内容日历/写复盘/看 ROI/想策略"等意图并正确派发；危险动作被闸拦住。
- **依赖**：v0.4 C5 + 人格库 + v1.6 注册表。

### Phase 2 · 三大高价值子 Agent（最快见效，约 3–4 周）

- **目标**：先点亮经理最高频、数据最齐的三块。
- **核心交付**：
  - **内容官**：直接复用 v0.6 营销顾问，扩展"内容日历排期 / 选题策划 / 多形态文案（信息流/短视频/白皮书）/ 品牌 TONE 校验"；
  - **洞察官**：基于营销库 + 活动效果库做"竞品打法分析 / 渠道 ROI / 营销归因 / 经营看板问答"，输出**可解释**结论；
  - **活动官**：活动策划框架生成、执行 SOP、活动复盘（读活动效果库 + 营销库案例）。
- **验收**：能回答"哪个渠道 ROI 最高、怎么调""帮我排 Q3 内容日历""这个活动复盘一下"；生成内容带溯源与 TONE 校验。
- **依赖**：Phase 0 + Phase 1。

### Phase 3 · 完整职能子 Agent（约 4–6 周）

- **目标**：覆盖 10 大职责域。
- **核心交付**：
  - **策略官**：市场定位、年度计划草稿、预算拆解与管控（接规则引擎）；
  - **品牌官**：品牌健康度、TONE 一致性巡检、品牌话术库维护；
  - **增长官**：投放文案/落地页优化建议、线索培育 MQL→SQL 策略、与销售 SLA 协同；
  - **公关官**：公关稿/口径生成、舆情预警、危机预案建议；
  - **协同官**：代理商/供应商协同、周报月报、预算 ROI 汇报材料自动生成（复用 OpsAgent）。
- **验收**：端到端跑通"策略→内容→活动→投放→线索→移交销售→复盘"全链路，关键节点有人确认。
- **依赖**：Phase 2。

### Phase 4 · 自治闭环（约 3–4 周）

- **目标**：从"你问它答"到"它主动管"。
- **核心交付**：事件驱动预警（舆情异动/活动 KPI 偏离/预算超支/内容排期空白主动推）；周期性自动产出（日报/周报/月经营会材料/内容日历自动补位）；自动线索培育与移交（基于 MQL 评分）。
- **验收**：模拟舆情异动能主动报警并给处置建议；周期报告按时自动生成。

### Phase 5 · 自进化（持续）

- **目标**：越用越像"资深"。
- **核心交付**：复盘自动沉淀进知识库（赢单/爆款案例/话术/坑）；检索与模型季度迭代；效果评估看板（内容采纳率、活动 ROI 提升、线索转化率、AI 建议采纳率）。
- **验收**：知识库月增长可量化；ROI 归因准确率持续提升。

> 总工期估算（核心研发）：约 **4–5 个月**到达 Phase 3 完整职能；Phase 4–5 持续迭代。可与 AI 销售经理并行推进（共享底座，省大量重复）。

## 七、推荐的 MVP 第一刀（先证明价值）

**建议 Phase 1 + Phase 2 合并为第一个可演示闭环**，范围刻意收窄：

- 营销经理人格 P-MKT + Supervisor 调度骨架（Phase 1）；
- **内容官 + 洞察官 + 活动官（Phase 2 三子 Agent）**；
- 数据仅用**已建成的营销资料库 + 轻量活动效果库**。

**为什么选这刀**：营销库已就绪（数据最齐）、价值最直观（内容生产/复盘/ROI）、风险最低（内容官复用 v0.6 已验证，写动作全走 Confirm 闸）、能最快给胜非一个"会当营销经理的 AI"演示。

**MVP 验收 demo**：打开工作台，"帮我排下 Q3 内容日历" → 内容官生成带 TONE 校验的日历；"最近竞品在打什么、我们怎么应对" → 洞察官给竞品拆解+对策+溯源；"这个活动复盘一下，ROI 怎么样" → 活动官生成带数据来源的复盘，提交前需人确认。

## 八、创业视角：差异化与商业模式（给胜非的额外参考）

| 维度 | 判断 |
|---|---|
| **定位差异化** | 不做"文案生成工具"（Jasper/Copy.ai 已红海），做"**能替经理做策略决策和全盘管理的 AI 营销经理**"——中枢编排而非单点功能。对标 Adobe GenStudio / HubSpot AI，但更强调**私有化 + 行业营销知识护城河**。 |
| **护城河** | 营销库 + 行业营销知识（打法/竞品/ROI 归因）+ 可解释 + 私有化部署。通用大模型没有你的行业营销数据与历史案例。 |
| **竞品站位** | 国际：Adobe GenStudio、HubSpot AI、Jasper；国内：有赞/微盟营销、各内容平台 AI。我们缺口在"全职能营销主管 Agent"这一层，且可和销售经理 Supervisor 形成"营销+销售"双中枢闭环——这是别人没有的。 |
| **商业模式** | 私有化项目制（中大型品牌/制造业大客户）+ SaaS 按席位/按调用量（中小）；"AI 营销经理"作为高阶套餐溢价点，可与"AI 销售经理"打包成"AI 经营中枢"。 |
| **合规卖点** | Confirm 闸 + 审计 + 密级隔离 + 品牌 TONE 校验，解决企业"不敢让 AI 擅自发文/投放/动预算"的顾虑——To B 落地刚需。 |

## 九、风险与待胜非拍板的事项

**主要风险**
- 营销数据割裂：活动效果/舆情/用户分层数据往往散落在投放平台、社媒后台，需打通才有 ROI 归因（先 Phase 0 治理，轻量起步）。
- 幻觉边界：对外发布/公关口径必须可解释+溯源+人确认。
- 过度自动化：发文/投放/预算等高风险动作必须 Confirm 闸，不能全自动。
- 成本：多 Agent + RAG + 大模型调用，需按调用量核算。

**需要胜非决策（决定下一步怎么切）**
1. **营销 vs 销售边界**：同意"AI 营销经理 与 AI 销售经理 并列双 Supervisor、共享底座、经线索 SLA 协同"的架构吗？还是希望做成一个"营销+销售"合并中枢？（影响架构与路由）
2. **行业聚焦**：先打透 B2B 制造业（已有 CPQ/招投标积累可作协同），还是泛行业/消费品牌？—— 影响知识库与话术建设。
3. **第一刀范围**：是否同意按第七节 MVP（内容官+洞察官+活动官）先做出可演示闭环？
4. **数据起步策略**：Phase 0 是先只接已建成的营销库（最快出 MVP），还是同步启动竞品库/活动效果库建设（更全但更慢）？
5. **人工介入深度**：Confirm 闸边界设多严（建议：一切对外发布/投放/预算动作都确认，内部分析/草稿生成可自动）。
