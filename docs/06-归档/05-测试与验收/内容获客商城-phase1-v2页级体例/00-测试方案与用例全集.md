## 1. 质量目标与原则

### 1.1 一句话目标

**每一研发 Step 必须同时通过：正常路径 + 异常/对抗路径 + API/前端自动化 + 字段边界/必填 + UI/UX；微信/公域先 Mock。只测正常操作 = 不合格。**

### 1.2 不可谈判原则

1. **前后端同验**：无「只测 API 算过」；页面功能未测 = 未交付。  
2. **用例先行**：本文件为权威用例库；脚本 ID 必须映射到本文 `TC-*`。  
3. **一步一验**：对齐执行计划；FAIL 即停，禁止带 P0/P1 进下一 Step。  
4. **Mock 先于真机**：微信支付、抖店 Webhook 默认 `SHOP_*_PROVIDER=mock`；真机为独立轮次。  
5. **证据留存**：每轮输出机器报告 JSON + 人工报告 Markdown/HTML；无证据不得签收。  
6. **主产品不破坏**：每轮必跑 `run_m0_m8.py`（RG-1）。  
7. **异常与正常同等强制**：**禁止只测 Happy Path**。每个可写操作必须覆盖校验失败 / 无权限 / 错状态 / 重复提交 / 越权 ID（见 [07-异常与对抗操作全集](./07-用例详表-异常与对抗操作全集.md)）；异常用例须断言「失败且无脏副作用」。P0 异常十连不过 → 本轮不通过。

### 1.3 测试对象分层

| 层 | 对象 | 自动化载体 |
|----|------|------------|
| L1 API | `/api/v1/admin/shop/*` · `/api/v1/shop/*` · `/api/v1/mp/shop/*` · `/integrations/*` | `verify_shop_m*.py` · `run_shop_all.py` |
| L2 Web UI | 平台 `/admin/shop/*` · 商家 `/shop/*` · 智营壳 A20/登录注册 | Playwright（复用 `docs/05-测试与验收/自动化测试/` 模式） |
| L3 小程序/H5 | 买家 M01–M15（`apps/mp`） | Playwright H5 / 后续小程序自动化 |
| L4 虚拟对接 | 微信 notify Mock · 抖店 Webhook Mock · 短信 Mock · OCR stub | 契约测试 + 幂等重放 |
| L5 UI/UX | 视觉一致性 · 操作习惯 · 无障碍基础 | 清单评分 + 截图基线（半自动） |
| L6 回归 | 主产品 CRM/Agent + 已验收商城批次 | `run_m0_m8` + `run_shop_all --through` |

## 2. 多轮测试计划（R0～R6）

| 轮次 | 名称 | 触发条件 | 范围 | 出口标准 |
|------|------|----------|------|----------|
| **R0** | 用例与环境就绪 | 开测前 | 本用例库评审签字；种子账号；Mock 开关；浏览器矩阵 | 用例评审通过；环境冒烟绿 |
| **R1** | 批次专项（随 M0f/M1…） | 每 Step 宣称完成 | 正常路径 + **异常包（07）** + 字段 + UX 子集 | 专项 100% PASS；**P0 异常十连过**；无未关 P0/P1 |
| **R2** | 批次回归 | R1 通过后 | 本批次 + 以往批次 `run_shop_all --through` | 串联全绿 |
| **R3** | 端到端业务链 | M3/M4/M5/M6/M7 各自首次绿后 | 私域购→履约；退款关权；上架闸 | 硬门槛 H1～H3 证据齐全 |
| **R4** | 虚拟对接全量 | M3+M7 Mock 就绪 | 微信 Mock · 公域 Mock · 短信 · OCR · 异常签名/重放 | Mock 契约 100%；幂等通过 |
| **R5** | UI/UX 专家轮 | 每端页面首次可点 + Phase1 冻结前 | §7 全部 UX 用例 + 跨页一致性 | UX 评分 ≥ 阈值；P0 体验缺陷清零 |
| **R6** | 发布门禁 / 真机选修 | Mx 签收或发版 | 全量回归 + 报告；可选真机微信/抖店 | 报告签发；真机轮单独签收 |

**并行规则**：商务未就绪时，R4 Mock 可签收「虚拟对接合格」；R6 真机标注 ⏸，不阻塞研发进入下一功能批次（但阻塞「生产公域上线」声明）。

## 4. 通用字段校验规则库（所有表单强制套用）

> 每个「可编辑栏位」至少覆盖：**空值 · 仅空格 · 最小合法 · 最大合法 · 超长 · 非法字符 · 类型错误 · 前后空格 trim**。  
> UI 与 API **双重断言**：UI toast/红字文案 + HTTP 状态/ `detail`。

### 4.1 类型规则

| 类型 | 必填空提交 | 边界 | 非法 | 期望 |
|------|------------|------|------|------|
| 手机号 `mobile` | 422 / 红字 | 11 位；`1[3-9]\d{9}` | 10/12 位、含字母、固话 | 拒绝；提示与 PRD 一致 |
| 身份证 `id_no` | 按主体 | 18 位校验位 | 15 位旧证（Phase1 是否支持写死）、含 X 大小写 | 按 PRD；不一致则 FAIL |
| 统一社会信用代码 | 个体/企业必填 | 18 位 | 17/19、小写 | 拒绝 |
| 金额（分） | — | `0`；最大按 PRD；负值 | 小数点字符串直传 | API 用分；UI 展示元 |
| 短文本 | 按字段 | min=1（必填）；max=字段长度 | emoji/SQL 片段 | 超长 422；XSS 存后须转义展示 |
| 长文本/富文本 | 按字段 | max | script 标签 | 存储可原样，**展示必须转义** |
| 枚举/下拉 | 必填未选 | 仅枚举值 | 篡改 option value | 422 |
| 日期/时间 | 按字段 | 过去/未来合法性 | 非法格式 | 422 |
| 文件上传 | 必填未传 | 类型白名单、大小上限 | exe、超大 | 拒绝 |
| 密码 | 注册必填 | 长度/复杂度按主站 | 弱密码 | 与主站一致 |

### 4.2 列表页五件套（每个列表页必测）

| ID 后缀 | 项 | 期望 |
|---------|-----|------|
| `-L01` | 默认加载 | 有分页、总数、空态文案 |
| `-L02` | 关键词搜索 | 命中/无命中；特殊字符不 500 |
| `-L03` | 快捷 Tab/状态筛选 | 与行状态一致 |
| `-L04` | 高级筛选展开 | 组合条件 AND；重置清空 |
| `-L05` | 分页 | 改 pageSize；末页；越界回落 |
| `-L06` | 行内操作矩阵 | 仅合法状态显示；无权限不渲染 |
| `-L07` | 排序（若有） | 升/降正确 |

### 4.3 权限矩阵（每个写操作必测）

| ID 后缀 | 场景 | 期望 |
|---------|------|------|
| `-P01` | 有权限角色 | 200/业务成功 |
| `-P02` | 无权限角色 | UI 无按钮 + API 403 |
| `-P03` | 跨租户 ID | 404（不暴露存在性）或 403 |
| `-P04` | 已清退/暂停商家 | 按 PRD 422/拦截 |
