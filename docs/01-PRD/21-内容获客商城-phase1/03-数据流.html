机审规则（F6 · 业务说明）

触发：商家 POST …/submit-review 成功写入 pending_review 后同步执行（与 INSERT shop_product_reviews 同事务）。结果写 review.auto_result / auto_flags，摘要同步 shop_products.compliance_flags。

项说明
扫描范围商品 name · subtitle · 简介/详情摘要 · cover_url（元数据）· 关联内容标题/正文摘要（专栏课时名、资料包文件名、服务说明）；均取自 snapshot_json 冻结快照

rule_code规则名判定要点默认级别典型处理

平台向商家结算已成交订单款（扣除平台服务费/类目费率）。与微信/抖店分账可并行；P05 为平台侧对账打款台账。白话说明 ⑦ 支付与结算 · 表见 04 §settlement · API §8.14.3 · 业务规则 06 §结算规则。

可结 T+7：订单支付满 7 自然日才可入池。F10 日跑 T+1：每日把可结订单/退款记入当期开放账期。出账默认周结：自然周关账每 tenant+shop 必出 1 条批次（含 net≤0）；仅 net>0 为 pending 待打款。负额 carried_forward 结转下期；吸收批次 paid 后同步更新源批次为 offset_settled。

步骤读写
1. 日跑入池前日新满足可结的 shop_orders；同期 refunds.succeeded记入当期开放账期（尚未出批次行）
2. 计费类目费率 category_fee_rules汇总 period_net_cents = gross − fee − reversal
3. 周关账出批账期结束；按 tenant+shop 汇总；读未抵扣 carried_forward 批次INSERT shop_settlement_batches + items。写 opening_balance_cents（≤0）。net>0 → pending；net=0 → closed；net<0 → carried_forward。含 period_carry_in 明细行（若有结转）
4. 运营确认batch.status=pending；净额 > 0P05-B confirm → paid；写 paid_at · transfer_voucher_url
5. 结转同步本批 opening_balance_cents<0同事务：被计入本批的 carried_forward 批次 → offset_settled；写 offset_by_batch_id · offset_settled_at
6. 打款失败银行/对公退回payment_failed；P05-C 重试（不回滚已 offset_settled 的源批次）
7. 关账回写批次达终态回写订单 settled_at（paid / closed / carried_forward / offset_settled）

Phase 1：日滚动入池 + 周关账出批 + 人工确认打款；不对接银行自动划付。与套餐 B2B 续费（§2.4.3）无关。
