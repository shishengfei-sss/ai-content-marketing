0一页摘要（给评审）

产品一句话

建设销售专属资料库：CRM/产品主数据继续做「事实真相源」，资料库做「可检索、可引用、可控权」的销售资产层；销售仍只在 CRM 录入，系统自动同步；AI 回答必须带来源，禁止无权限批量导出。所有读写强制租户隔离，跨租户零可见。

要解决的问题

  • 跟进、附件、报价、标书、产品说明散落，找材料慢
  • 经验难复用，新销售靠口口相传
  • 营销知识库不适合承载客户隐私与底价
  • AI 若直接扫 CRM 表，易幻觉且难做密级

硬决议（本 PRD）

  • 租户隔离：一切索引/检索/溯源/重索引以 tenant_id 为第一谓词；跨租户 0 命中、0 泄露
  • 独立域：/sales-kb/*，不混入 knowledge_*
  • Core + Adapter：本系统 CRM 为第一 Adapter，预留多源
  • 全开源私有化：禁止商用向量库/知识库 SaaS
  • 产品数据必进：规格/参数/说明书进库；成本价默认不进 AI 正文
关联：老板一页纸结论 · 小白方案 · 与 CRM 打通（A′）· 产品主数据 PRD（v1.4）· 现有 knowledge_service（营销 RAG）

7检索、混合召回与溯源

7.1 检索流水线（强制顺序）

1) Auth → 解析可信 tenant_id（JWT/API Key；忽略请求体伪造 tenant）
2) PrincipalScope（tenant 已锁定 + owners/territories + max_secrecy + entity allowlist）
3) 元数据硬过滤：tenant_id = 会话租户（必选）+ 其它 filter
   ——禁止「先全库/跨租户向量再过滤」
4) Hybrid：向量 TopK + 关键词/BM25 TopK → RRF/加权融合（均在租户过滤之后）
5) 业务重排：同客户/同产品加权；过期降权；停用产品降权
6) 组装 snippets + citation_id；敏感字段脱敏
7) GET citation：再次校验 citation 所属 tenant_id == 会话租户，否则 404（不暴露是否存在）

7.2 反幻觉约束

风险对策
编造电话/金额系统提示仅用 snippets；结构化卡优先；无命中拒答
串客户支持强制 filter customer/lead；命中后校验实体一致性
过期信息返回 updated_at；filter status=active 默认开启
成本价泄露产品 chunk 构建阶段剥离 cost_price

8租户隔离、权限、密级与审计

8.0 租户隔离（硬约束 · 优先于密级与私海）

隔离优先级：租户 → 密级 → CRM Scope（本人/团队/区域）。未通过租户校验的请求不得进入后续逻辑。

层面要求落地细则
身份与会话 租户来自可信凭证 用户 JWT / Agent API Key / Ingest Key 均绑定唯一 tenant_id；请求体、Query、Header 中的「目标租户」若与凭证不一致 → 403；禁止超级接口「传 tenant_id 查别家」除非平台超管独立审计通道（本包默认不做）
关系数据库 行级必含租户 所有 sales_kb_* 查询第一谓词 tenant_id = :ctx；唯一索引含 tenant_id；citation/document/entity/job 读取均二次校验租户
向量库 检索不可跨租户 推荐：每租户独立 collection，或统一 collection 但强制 payload filter tenant_id 且代码层断言 filter 已附加；单元测试覆盖「漏传 filter 则拒绝执行」
对象存储 路径租户隔离 存储键前缀 /{tenant_id}/sales-kb/...；签名 URL 不得跨租户生成；下载前校验文档 tenant
任务队列 任务携带租户 Outbox/Job payload 必含 tenant_id；Worker 处理前与源实体 tenant 比对，不一致丢弃并告警
Agent / Ingest Key 一 Key 一租户 禁止一张 Key 绑定多租户；轮换/吊销按租户执行；审计日志带 tenant_id
缓存 键含租户 Redis 等缓存 key 必须含 tenant_id；禁止仅用 chunk_id 做全局缓存键
平台招标 L1 不直接进他租户 KB 平台池材料仅在认领/匹配为租户线索后，以该租户写入销售 KB；未认领的 L1 不对租户销售 KB search 开放
错误与枚举 防侧信道 跨租户访问 citation/document 统一 404（非 403），避免探测他租户资源是否存在
运维重索引 范围锁租户 /reindex 仅允许当前租户；禁止「全平台 reindex」API（平台运维走离线脚本+双人复核，不在产品 API 暴露）
【业务】 企业 A 的销售、AI、导出任何情况下都看不到企业 B 的线索/产品/报价资料；即使产品名称相同也互不影响。
【开发】 中间件注入 ctx.tenant_id；Repository/Search 无 tenant 参数则无法编译或运行期断言失败；CI 必跑跨租户穿透用例（见 AC-05/AC-05b/AC-05c）。

8.3 AI 专属限制

  • API Key 绑定单一 tenant_id，请求不得改绑
  • top_k ≤ 20（可配置上限）
  • max_secrecy 默认 ≤ L2；升 L3 需本租户开关 + 脱敏
  • 禁止调用 export / bulk 下载客户敏感字段
  • RPM / 日配额；全量审计 api_key_id + tenant_id + filters + hit_count

export≥365 天 + 审批单号（P1）
【业务】权限申请 跨团队看线索走审批；L3/L4 高密资料需事由；不得要求 AI「导出全部客户手机」。
【开发】行级过滤 所有 search 必须先锁 tenant_id 再套 scope/密级；跨租户用例自动化必测；向量侧与 SQL 侧双重约束；漏 filter 直接失败而非降级放行。

12业务规则
ID规则
BR-SKB-00租户隔离：任何读写以凭证 tenant_id 为唯一租户；跨租户访问统一按不存在处理（404）；向量/SQL/对象存储/缓存/队列全链路强制租户谓词
BR-SKB-00bAgent/Ingest API Key 一 Key 一租户；禁止多租户共用 Key
BR-SKB-00c平台招标 L1 未认领前不入租户销售 KB 检索面；认领后仅写入认领租户
BR-SKB-01CRM/产品主数据为真相源；KB 投影不一致时以源系统为准并触发重索引（同租户内）
BR-SKB-02销售 KB 与营销 knowledge 存储、API、Agent 工具强制隔离
BR-SKB-03检索必须先 tenant_id，再 Scope/密级硬过滤，再召回
BR-SKB-04无检索命中时，Agent/UI 不得编造客户事实
BR-SKB-05所有命中必须可解析 citation → document → source entity
BR-SKB-06cost_price 默认不进入可检索正文与 Agent 上下文
BR-SKB-07报价类默认 L3；draft 报价仅 owner（及 list_all 角色）可见
BR-SKB-08L4 默认不对 Agent Key 开放
BR-SKB-09Agent 角色禁止 sales_kb.export 与批量敏感字段拉取
BR-SKB-10幂等键：(tenant, source_system, entity_type, external_id) 与文档 content_hash
BR-SKB-11软删源实体 → KB status=deleted 且向量不可检索
BR-SKB-12跨 source_system 的 deep_link 由 LinkResolver 生成；未知源只展示只读元数据
BR-SKB-13产品停用仍可检索但必须标记 inactive，UI/Agent 需提示
BR-SKB-14单次 search top_k 服务端强制封顶（默认 20）
BR-SKB-15写入/索引时 tenant_id 为空或与源实体不一致 → 拒绝入库并告警
BR-SKB-16/reindex 仅能操作当前租户数据；产品 API 不提供跨租户批处理
13非功能与技术约束

13.1 开源组件（允许清单）

用途组件
业务/元数据PostgreSQL
向量（生产倾向）Qdrant（开源）；小规模可 pgvector 过渡
对象存储MinIO 或沿用现有附件存储 + 后续迁移
队列Redis + ARQ/Celery（与现栈对齐即可）
Embedding本地开源模型（如 bge-m3 / bge-large-zh）；可先复用现有本地 embedding 能力做 P0
禁止任何商用托管向量库、付费知识库平台作为必选依赖

13.2 性能与可靠性（目标）

指标P0 目标
索引延迟（活动文本）P95 ≤ 5 min（异步）
检索延迟P95 ≤ 1.5s（万级 chunk 单机）
租户/权限穿透跨租户 0 命中、0 枚举；跨私海 0 泄露；漏 filter 用例必须失败
备份PG 日备；向量快照日备（P1 完备）；恢复演练验证租户数据不串

13.3 租户隔离测试（CI 必选）

  • 租户 A 写入 lead/product 文档后，租户 B 的 search / citation / document / status 均为空或 404
  • 租户 B 伪造 A 的 external_id / citation_id 不得返回 200
  • 向量检索故意去掉 tenant_id filter 时，服务拒绝执行（断言/异常），而非返回数据
  • Agent Key（租户 A）携带租户 B 的 filter 尝试扩大范围 → 忽略或 403，且仅返回 A 数据
